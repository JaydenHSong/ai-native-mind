# Context Rot 예방: 기억력을 잃어가는 AI 구하기

## 쉽게 읽기

**한 줄**: 채팅이 길어지면 **중요한 말이 묻히고 비용만 커진다**. 그래서 **짧게 유지(단기) → 요약(중기) → DB에만 두고 필요할 때 검색(장기)** 로 나눈다.

| 계층 | 비유 |
|------|------|
| **단기** | 책상 위 연습장 |
| **중기** | 과목별 요약 노트 |
| **장기** | 도서관(벡터 DB + RAG) |

## 🏫 중학교 1학년 2학기: "어제 한 말을 왜 자꾸 까먹지?"

AI와 길게 대화하다 보면 어느 순간 앞서 했던 말을 까먹거나, 엉뚱한 맥락을 짚는 현상을 경험해 보셨을 겁니다. 이것을 **컨텍스트 썩음(Context Rot)** 또는 **컨텍스트 엔트로피(Context Entropy)**라고 부릅니다.

## 한줄 설명

대화 기록(메모리)이 너무 길어질 때 핵심 정보를 요약하고 분류하여 저장하는 **'3계층 메모리 설계 패턴'**입니다.

---

## 🚨 문제 상황: 쓰레기장이 되어버린 AI의 머릿속

우리가 AI와 주고받는 모든 대화(채팅 로그)는 차곡차곡 쌓여서 다음 대화에 참고자료로 쓰입니다. 
하지만 대화가 수천 줄을 넘어가면 다음과 같은 일이 발생합니다.
1. **건초더미에서 바늘 찾기 (Needle in a Haystack):** 핵심 정보가 쓸데없는 대화("네 알겠습니다", "아 그게 아니라요") 사이에 파묻혀 못 찾습니다.
2. **비용 폭탄 (Token Limit):** 쓸모없는 옛날 대화까지 매번 다 읽게 만들면, API 호출 비용(토큰)만 기하급수적으로 늘어납니다.

---

## 🛠️ 해결 방법: 3계층 메모리 (단기, 중기, 장기)

학생이 시험 기간에 공부할 때, 모든 책을 다 펼쳐놓지 않고 **필기 노트(단기)**, **교과서(중기)**, **도서관(장기)**으로 나누는 것과 똑같습니다.

### 1계층: 단기 기억 (Short-term / Working Memory)
*   **비유:** 책상 위에 펼쳐둔 연습장.
*   **내용:** "지금 당장" 주고받고 있는 **최근 5~10번의 대화**만 원본 그대로 유지합니다.
*   **특징:** 빠르고 생생하지만 오래 못 갑니다.

### 2계층: 중기 기억 (Mid-term / Episodic Memory)
*   **비유:** 과목별로 요약해둔 서브 노트.
*   **내용:** 대화가 10번을 넘어가면, 백그라운드에서 요약 에이전트(Summarizer)가 출동합니다. 방금 전 대화를 "사용자는 A를 B로 바꾸길 원했음" 이라고 한 줄로 **요약**해서 저장하고, 원본 대화는 날려버립니다.
*   **특징:** 토큰을 획기적으로 아낄 수 있습니다.

### 3계층: 장기 기억 (Long-term / Semantic Memory)
*   **비유:** 도서관 서고 (Vector DB).
*   **내용:** 어제 했던 프로젝트 기획안, 3달 전의 버그 픽스 기록 등은 단기/중기 기억에 넣지 않습니다. 대신 **벡터 데이터베이스(Vector DB)**에 차곡차곡 인덱싱해둡니다.
*   **작동 방식 (RAG 패턴):** AI가 "그때 그 기획안"이라는 말을 듣는 순간, 도서관(DB)에 쏜살같이 뛰어가 관련된 페이지 한 장만 쏙 뽑아서 컨텍스트에 밀어 넣습니다.

---

## 🎯 적용 예시: "코딩 에이전트의 기억법"

에이전트가 코딩을 하다가 막혔습니다.
1. 방금 친 명령어와 에러 로그는 **단기 기억**에 그대로 남겨두고 고민합니다.
2. 어제 성공적으로 짰던 코드의 전반적인 구조(아키텍처)는 **장기 기억(DB)**에서 검색해 참고합니다.
3. 오전 내내 삽질했던 잡다한 대화 기록은 "이 라이브러리는 현재 버전과 호환 안됨" 이라는 한 줄로 요약해서 **중기 기억**에만 남깁니다.

이 패턴을 도입하면 AI가 100시간을 코딩해도 길을 잃지 않습니다!
