# 나만의 에이전틱 서비스 아키텍처 설계 (Capstone)

## 쉽게 읽기

**한 줄**: 지금까지 배운 **컨텍스트·하네스·툴·오케스트레이션·HITL**을 한데 모아, **웹훅 → DB 상태 → RAG → 샌드박스 → 병렬 리뷰 → 사람 승인** 같은 **실서비스 한 바퀴**를 그려 본다.

| 말 | 뜻 |
|----|-----|
| **웹훅** | 깃허브 등에서 “일 났어”라고 **HTTP로 콕 찌르기** |
| **HITL** | 위험한 건 **사람 OK** 전엔 실행 안 함 |

## 🎓 중학교 3학년 2학기: 졸업 작품

3년 동안 정말 고생 많았습니다! 여러분은 이제 프롬프트를 다루고, 하네스(통제기)를 채우고, 툴(손발)을 달고, 여러 에이전트를 지휘(오케스트레이션)하는 법을 모두 배웠습니다.

이제 이 모든 것을 결합하여, **나 혼자 노트북에서 돌리는 스크립트가 아니라, 전 세계 누구나 접속할 수 있는 '웹 서비스(서버)'로 배포하는 아키텍처**를 설계해 봅시다.

---

## 🏗️ 졸업 설계: "AI 코드 리뷰 봇 (SaaS) 만들기"

목표: 깃허브(GitHub)에 코드가 올라오면, AI 에이전트들이 코드를 리뷰하고 댓글을 달아주는 서비스를 구축합니다.

### 1단계: 진입점과 상태 관리 (오케스트레이터의 뼈대)
*   **트리거 (시작점):** 개발자가 코드를 `Push`하면 우리 서버로 웹훅(알림)이 날아옵니다.
*   **상태 저장 (Database):** 알림이 오면 먼저 DB에 "작업 생성됨(Status: Pending)"을 기록합니다. (에이전트가 중간에 죽어도 어디서 재시작할지 알기 위함입니다.)

### 2단계: 컨텍스트 수집 (1학년 과정 활용)
*   **RAG (Vector DB):** 에이전트에게 냅다 코드를 던지는 대신, 벡터 DB를 검색해 "이 회사의 기존 코딩 스타일(규칙)"을 컨텍스트로 쥐여줍니다. (Context Engineering)

### 3단계: 하네스와 보안 샌드박스 (2학년 과정 활용)
*   **격리 (Sandbox):** 코드를 컴파일해 봐야 버그가 있는지 알 수 있습니다. 내 서버에서 돌리면 해킹 위험이 있으니, 일회용 Docker 컨테이너(샌드박스) 안에서 코드를 빌드(Tool)해 봅니다.
*   **센서 (Sensor):** 빌드 중에 에러가 나면? 그 에러 로그(피드백)를 잡아서 에이전트에게 다시 넘겨줍니다.

### 4단계: 에이전트 오케스트레이션 (3학년 과정 활용)
*   **병렬 + 평가 루프 혼합 (Orchestration):**
    1. 코드가 10개의 파일이면, 10마리의 [리뷰 에이전트]를 **병렬**로 띄워서 동시에 리뷰합니다.
    2. 리뷰 결과가 나오면, 깐깐한 시니어 역할의 [평가자 에이전트]가 그 리뷰가 너무 공격적이지 않은지, 진짜 맞는 말인지 **검증(Evaluator)** 합니다.
    3. 최종 통과된 리뷰만 취합합니다.

### 5단계: 인간과 협력 (Human-in-the-loop)
*   에이전트가 "이 코드는 당장 삭제해야 해!"라고 극단적인 리뷰를 썼다면? 
*   서비스 관리자(인간)의 화면(대시보드)에 "위험한 리뷰 승인 대기 중"으로 띄워줍니다. 인간이 OK 버튼을 눌러야만(HITL) 최종적으로 깃허브에 댓글이 달립니다.

## 🚀 당신은 이제 'Agent Architect'입니다.

단순히 OpenAI API를 호출하는 튜토리얼 수준을 넘어,
**예외 상황(실패)을 예측하고, 권한을 통제하며, 상태를 안전하게 관리하는 전체 시스템**을 그릴 줄 알게 되었습니다.

축하합니다! 이제 진짜 프로덕션(실무) 환경에서 AI 에이전트를 맘껏 설계하고 뛰어놀게 만드세요!
