# §1. 오늘의 데일리 (금요 ingest)

세 편은 어제(2026-05-14)에 식별된 *2x3 좌표계의 빈 칸*들을 향해 정확히 떨어진다.

| 좌표 | 어제 상태 | 오늘 채움 |
|---|---|---|
| (Tooling, 정형화) | (open) | **ACDL** — context 합성 표기 언어 (Peleg Pelc et al., 2026-05-03) |
| (Descriptive, 측정) | (open) | **Constraint Decay** — 8 framework × 100 task 백엔드 경험 정량 (Dente et al., 2026-05-07) |
| (Tooling, 측정) | WildClawBench 1점 | **GroupMemBench** — multi-party memory 측정 (Yang et al., 2026-05) |

## 1-A. ACDL — Context 합성의 *표기 언어*

**한 줄**: "Context Engineering이 학문이라면 *기호*가 있어야 한다 — role-message sequence · dynamic content · time-indexed reference · conditional/iterative structure 4구성, 손그림과 정형 코드 양쪽으로 같은 의미를 보장."

- 4 구성: role-message sequence / dynamic content / time-indexed reference / conditional·iterative
- CAIS '26 채택. <http://www.acdlang.org> 에 tooling·examples·문서 공개.
- → [[concepts/context-engineering]] "2026-05-15 보강" 섹션 추가.

**짝**: Mise en Place(2026-05-12)가 *프로세스*를 정한다면 ACDL은 *결과 구조*를 그린다. GROUNDING.md(2026-05-12)가 *constraint 텍스트*를 정한다면 ACDL은 그 텍스트가 *prompt에 어떻게 주입되는지*를 적는다.

## 1-B. Constraint Decay — 구조 제약 누적 시 성능 −30점

**한 줄**: "기능만 보던 벤치마크는 LLM 에이전트의 *현실*을 가렸다 — 구조 제약(아키텍처·DB·ORM)을 누적 부과하면 capable model도 30점 추락, 약한 config는 0점에 수렴."

- 100 task (80 greenfield + 20 feature-impl) × 8 web framework × unified API contract
- Framework sensitivity: Flask 강함 / FastAPI · Django 약함
- Root cause 1순위: **Data-layer defect** (query composition, ORM runtime violation)
- → [[patterns/ai-code-review]] "2026-05-15 보강" 섹션 추가: Plan-Review-Execute에 **Phase 2.5 Structural Verify** 끼우기.

**짝**: 어제 the *3-stage Verify-Before-You-Fix*(05-13)가 *exploit 재현*(보안 verifier)이었다면, Constraint Decay는 *구조 idiom*(framework verifier). 같은 Review layer, *다른 verifier*.

## 1-C. GroupMemBench — Multi-Party Memory 첫 측정

**한 줄**: "메모리 시스템들이 *1:1 setup*만 가정해 왔다 — group/channel 도입하면 최강 시스템도 46.0%, knowledge update 27.1%, term ambiguity 37.7% — 단순 BM25가 대부분의 agent memory system을 *따라잡거나 능가*한다."

- 6 question category × adversarial query × multi-party 대화 합성 (graph-grounded synthesis)
- Theory-of-Mind 속성 (audience-adapted language) 측정 표면 등장
- → [[concepts/ai-memory-systems]] "2026-05-15 보강" 섹션 추가.

**짝**: ZenBrain(2026-05-03)의 *Autobiographical/Self* layer가 정확히 GroupMemBench의 (ii) speaker-grounded belief — ZenBrain은 *처방*(architecture), GroupMemBench는 그 처방이 부재한 시스템들의 *측정*.

## 1-D. 한 그림으로 잇기

```
     Context spec      Code structure       Memory ingestion
        (ACDL)        (Constraint Decay)    (GroupMemBench)
           │                  │                    │
           ▼                  ▼                    ▼
   "어떻게 적는가"        "왜 무너지는가"        "무엇이 사라지는가"
        표기 ←──────── 측정 ────────→ 측정
   (tooling, 정형화)  (descriptive, 측정) (tooling, 측정)
```

세 편 모두 *모델 capability가 아니라 모델 주변 표면(spec · structural constraint · ingest)*을 다룬다. → §2의 4일 합치기로 자연 연결.

# §2. 주간 리뷰 (05-12 → 05-15)

## 2-A. 한 주를 한 문장으로

> **"model alone is not enough — engineer the layer above"** 는 한 주 내내 같은 문장이었지만, 다루는 layer가 *매일 한 칸씩 위로 올라갔다.*

| 날짜 | layer 위치 | 3 source |
|---|---|---|
| 2026-05-12 | **모델 아래 세 레버** (workflow 입구 / eval 뒤 / invocation 위) | MEP · JRH · GROUNDING.md |
| 2026-05-13 | **출력 직전** 게이트 (3 도메인: text / code / embodied) | GSAR · Verify Before You Fix · Affordance Harness |
| 2026-05-14 | **모델 위** layer 전체 (학습 / 정형화 / 측정) | Zhang RL traces · Zhong/Zhu 11 책임 · WildClawBench |
| **2026-05-15** | **layer를 *적고*, *재고*, *재단한다*** (notation · structural eval · memory eval) | ACDL · Constraint Decay · GroupMemBench |

→ 4일이 누적되면 "**layer 사다리**"가 된다. 사다리의 4단을 4일 동안 *서로 다른 시점*(아래 / 직전 / 위 / 옆-표기)에서 본 셈.

## 2-C. 중복·압축 후보 — 살리되 합치기

작업 원칙: **본문·링크 무삭제**, 다만 *교차 참조 요약*만 새로 추가.

### 압축 후보 1: Wei 5 dimension ↔ Zhong/Zhu 11 책임 통합

| 시점 | 방법론 | 단위 |
|---|---|---|
| 2026-04-20 (Wei) | 70-project empirical | 5 design dimension (subagent / context / tool / safety / orchestration) |
| 2026-05-13 (Zhong/Zhu) | conceptual prescriptive | 11 component responsibility |

이미 [[concepts/harness-engineering]] "2026-05-14 보강" 섹션 *Wei vs Zhong/Zhu 비교 표*가 존재 — *압축 가능* 그러나 *압축 불필요* (각 표가 다른 시점·다른 grain). **결정: 그대로 유지**, 단 두 표 사이에 *cross-link 한 줄*("두 표는 같은 layer를 *empirical*과 *prescriptive*로 본다") 추가.

→ 변경 없음 (이미 충분히 압축된 상태로 판단). Lint check 통과.

### 압축 후보 2: 3 도메인 verifier (text / code / embodied)

| 시점 | 도메인 | verifier 종류 |
|---|---|---|
| 2026-05-13 GSAR | text | 4-judge consensus + evidence-weighted score |
| 2026-05-13 Verify Before You Fix | code | execution trace + exploit reproduction |
| 2026-05-13 Affordance Harness | embodied | skill output + prior |
| **2026-05-15 Constraint Decay** ← 오늘 | code | **static framework idiom checker** (functional verifier 옆에 *structural verifier*) |

→ 4번째 verifier 유형(structural)이 추가됨. [[concepts/harness-engineering]] "2026-05-13 보강" 섹션의 verifier 비교 표 한 행 추가 후보 (단 single-source라 보류, 06월에 multi-source가 되면 추가).

→ 결정: 본 journal entry §1-B에 *링크로* 명시, harness-engineering 본문은 *손대지 않음* (over-add 회피, Karpathy 원칙 3. Surgical Changes).

### 압축 후보 3: 메모리 benchmark — ZenBrain 처방 ↔ GroupMemBench 측정

[[concepts/ai-memory-systems]]에 ZenBrain(2026-05-03 보강)이 *처방*으로, 오늘 GroupMemBench가 *측정*으로 동시 존재. 둘은 동일 layer의 *다른 시점* — *압축하면 한 쪽이 사라진다*. **결정: 그대로 유지**, GroupMemBench 보강 섹션 안에 "ZenBrain의 7계층 중 *Autobiographical/Self*가 정확히 GroupMemBench의 (ii) speaker-grounded belief tracking"이라는 *한 줄 cross-link*만 추가됨 (이미 §1-C 작업에 포함).

### 압축 후보 4: 일지 메타 (4일 연속 "model alone is not enough")

journal 05-12, 05-13, 05-14, 05-15 네 일지가 모두 같은 한 문장으로 닫힌다. **압축 가능 여부**: 일지는 *시간순 기록*이라 압축 부적합. 다만 [[campaign-map]] 또는 [[overview]]에 *"Above-the-Model Layer week (2026-05-12 ~ 05-15)"* 한 절 추가 후보. **결정: 보류** (1주는 표본 작아 별도 페이지 신설 비효율, 4주 누적 시 재검토).

## 2-E. 자율 결정 사항 (사용자 부재)

- **3편 선택**: 어제 좌표계의 빈 칸을 *정확히 3개 채우는* 조합으로 ACDL (tooling-정형화) / Constraint Decay (descriptive-측정) / GroupMemBench (tooling-측정 추가) 선택. Agentic AI Survey 2510.25445는 *descriptive-학습* 축 미충당이라 다음 주로 이월 (단, §2-A의 layer 사다리 framing에서 *간접 인용*만).
- **WebFetch rate limit**: GroupMemBench는 abstract만 fetch 성공, 본문 미독. raw 파일에 *abstract-level 인용* 한계 명시. ACDL·Constraint Decay는 abstract 완전 fetch.
- **새 페이지 신설 보류**: ACDL용 신규 페이지(예: `concepts/context-notation`) 유혹 있었으나 single-source이므로 [[concepts/context-engineering]] 내부 섹션으로 흡수. 추후 multi-source가 되면 분리 재검토.
- **harness-engineering 본문 무수정**: Constraint Decay가 verifier 4번째 유형(structural)을 추가하지만, 어제 5-13 verifier 비교 표(3 도메인)에 행 추가는 over-add 위험 — *journal에서만* 명시.
- **압축 작업 4건**: 모두 *그대로 유지* 결정. 위키의 본문/링크가 한 줄도 삭제되지 않음 (사용자 룰 준수).
- **Wei 5 dim과 Zhong/Zhu 11 책임 통합 표**: [[concepts/harness-engineering]]에 이미 존재함을 확인. 추가 작업 불필요.
