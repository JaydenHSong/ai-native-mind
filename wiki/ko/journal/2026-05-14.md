# 2026-05-14 학습 일지 — 목요 데일리: Above-the-Model Layer

## 이 글을 읽는 법 (30초)

어제(2026-05-13)는 **"출력 직전 verification gate"**를 도메인별(text / code / embodied)로 잠갔다. 오늘 3편은 한 칸 더 위에 위치한 **"모델 위 layer 전체"**에 대해 같은 질문을 다른 시점으로 던진다:

| 시점 | 질문 | 논문 |
|---|---|---|
| **학습 시점** | Multi-agent *조율 자체*를 어떻게 RL로 학습 가능한 대상으로 보나? | Zhang, "RL for LLM-based Multi-Agent Systems through Orchestration Traces" ([arXiv:2605.02801](https://arxiv.org/abs/2605.02801), 2026-05-04) |
| **정의 시점** | "Harness"가 책임지는 것은 정확히 무엇인가? | Zhong & Zhu, "AI Harness Engineering: A Runtime Substrate for Foundation-Model Software Agents" ([arXiv:2605.13357](https://arxiv.org/abs/2605.13357), 2026-05-13) |
| **측정 시점** | Production-like runtime에서 *진짜* 점수는 얼마인가? | InternLM, "WildClawBench: Real-World, Long-Horizon Agent Evaluation" ([arXiv:2605.10912v1](https://arxiv.org/abs/2605.10912v1), 2026-05-11) |

세 시점이 공통으로 말하는 한 줄: **모델 하나 키워서 reliability를 푸는 시대는 끝났고, "모델 위 layer"를 학습·정형화·측정 *세 방식 모두로* 다뤄야 한다.**

## 한 그림으로 잇기

```
                       ┌─────────────────────────┐
                       │   Model (weights)       │  ← 한 시점의 capability
                       └─────────┬───────────────┘
                                 ▼
   ┌────────────────────────────────────────────────────┐
   │           Harness layer (runtime substrate)        │  ← Zhong/Zhu: 11 책임
   │  task spec · context · tool · proj mem · task     │
   │  state · observability · failure attribution ·    │
   │  verification · permission · entropy audit ·      │
   │  intervention recording                            │
   └────────────────┬───────────────────────────────────┘
                    ▼
   ┌────────────────────────────────────────────────────┐
   │      Orchestration decisions (trace graph)         │  ← Zhang: RL 대상
   │  spawn / delegate / communicate / aggregate / stop │
   │  ↑ 5 sub-decision × 8 reward family ×              │
   │    8 credit unit (message-level counterfactual 공백) │
   └────────────────┬───────────────────────────────────┘
                    ▼
   ┌────────────────────────────────────────────────────┐
   │   Environment (Docker, real tools, real horizon)   │  ← WildClawBench: 측정
   │   60 task · ~8 min · 20+ tool calls · hybrid grade │
   │   Best (Opus 4.7) = 62.2% / 모든 model < 60%        │
   └────────────────────────────────────────────────────┘
```

세 layer 모두 *모델 위*에 있고, 세 paper는 같은 layer를 **학습 가능한가 / 정형화 가능한가 / 측정 가능한가**를 각각 답한다.

## 3소스 요약

### 1) Zhang — Orchestration as RL Target (학습 가능성)

핵심: **수작업 디자인 패턴(Anthropic 6대)에서 *학습되는 정책*으로**.

- 3 기술 축: 8 reward family / 8 credit unit / 5 sub-decision
- 새 reward family **orchestration reward**: parallelism speedup · split correctness · aggregation quality
- 학습 공백 **stopping decision**: May 4, 2026 snapshot에서 explicit RL training method 0건
- 학습 공백 **message-level counterfactual credit**: 84-entry pool에서 sparse
- 산업 평행 evidence (학술 검증 아님): Kimi Agent Swarm / OpenAI Codex / Anthropic Claude Code
- Artifact: 84-entry pool + 32-record exclusion log + **JSON schema for replayable orchestration trace** (1인 개발자에게 직접 쓸모)

→ [[concepts/ai-orchestration]] "2026-05-14 보강" 섹션 신설.

### 2) Zhong & Zhu — Runtime Substrate (정형화)

핵심: **"Capability emerges from model-harness-environment system"** + **11 component responsibility** enumeration.

| 책임 | 핵심 |
|---|---|
| 1 Task spec | 무엇을·언제 끝 |
| 2 Context selection | 노출할 파일·메모리 |
| 3 Tool access | 액션 schema·permission |
| 4 Project memory | 장기 — repo state, lesson |
| 5 Task state | 단기 — plan·todo |
| 6 Observability | trace·metric·log |
| 7 Failure attribution | 누구 탓 (model·tool·prompt·env) |
| 8 Verification | "완료"의 입증 |
| 9 Permission | sandbox·HITL gate |
| 10 Entropy auditing | 결정 다양성·반복 stability |
| 11 Intervention recording | HITL을 *데이터*로 |

**Wei 5 dimension(2026-04-20)과 비교**: Failure attribution(7) / Entropy audit(10) / Intervention rec(11) — 이 3 책임이 Wei taxonomy에 없던 *증분*. 어제 RAND JRH·GSAR가 만들던 신호들이 자연스럽게 자라난 한 layer 위 책임.

→ [[concepts/harness-engineering]] "2026-05-14 보강" 섹션 신설.

### 3) WildClawBench — Real-World Long-Horizon (측정)

핵심: **production-like runtime에서 모델 capability 곡선이 평탄하다**.

- 60 task (EN 36 + CN 24, multimodal 26 + text 34)
- 평균 ~8 분 wall-clock, 20+ tool calls
- Docker 격리, 실 CLI 에이전트 하네스 4종(OpenClaw / Claude Code / Codex / Hermes)
- Hybrid grading: rule check + env audit + LLM/VLM judge
- 19 frontier model — **Best Opus 4.7 = 62.2% / 다른 모든 모델 < 60%**

→ 이 정량은 Zhong/Zhu의 *capability ≠ model* thesis의 **경험적 증거**다. → [[concepts/llm-evaluation]] "2026-05-14 보강" 섹션 신설 + 3 layer 재정렬 표(judge / single output / trace).

## 자율 결정 사항 (사용자 부재)

- **3편 선택**: 어제 명시된 후보 풀 중 *Survey(arXiv 2510.25445)*는 여전히 금요 weekly review용으로 reserve. 대신 (a) fresh May 2026 source (모두 published 5/4·5/11·5/13), (b) *모델 위 layer*라는 공통 주제, (c) 빈 위키 자리(orchestration RL은 아직 없었음) — 세 기준 만족.
- **WebFetch rate limit**: Zhang abstract는 fetch 성공, Zhong/Zhu와 WildClawBench는 search-engine snippet만 확보. Raw 파일과 wiki 섹션 모두 *abstract-level 인용*임을 한계로 명시. 본문 정독 후 update 가능.
- **새 책임 페이지·새 패턴 페이지 신설 보류**: 11 책임 각각을 페이지로 만들 유혹 있었으나 single-source이므로 *기존 [[concepts/harness-engineering]] 안의 표*로 추가. 책임 #7(Failure attribution)·#10(Entropy audit)·#11(Intervention rec)이 multi-source가 되면 그때 분리 검토.
- **WildClawBench의 "Opus 4.7"** 표기 채택: 어제 GSAR 4-judge에서 이미 *opus-4-7* 표기를 썼고, llm-stats·Vellum·Anthropic news 모두 일치 → 본 위키 일관 유지.
- **[[comparisons/agent-eval-frameworks]] 갱신 보류**: 6대장 + JRH(어제) + WildClawBench(오늘) 합치면 *프레임워크/judge/환경* 3 categorial 차이가 한 표에 섞인다. 카테고리 혼합 회피, 본 페이지(`llm-evaluation`)의 *3 layer 재정렬 표*로 처리. comparisons 페이지 update는 별도 case로.
- **어제 self-declared prediction** ("judge reliability가 eval 프레임워크 글에 표준 항목으로 등장") 검증: WildClawBench hybrid grading이 *judge를 셋 중 하나의 신호로* 쓰는 게 *간접 증거*. 강한 조건(eval 프레임워크 직접 등재)은 아직 미확인 — 금요 weekly review에서 lint check.
