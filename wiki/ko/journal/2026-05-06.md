# 2026-05-06 학습 일지 — 수요 데일리: 하네스가 자기 자신을 고치기 시작한다

## 이 글을 읽는 법 (30초)

자동 데일리 인제스트(스케줄러). AI 에이전트 엔지니어링 자료 3편을 `raw/articles/`에 정리하고, 관련 위키 페이지에 **추가만** 했다 (기존 본문·링크 보존).

세 글을 한 그림으로 묶으면 — **하네스가 자기 자신을 고치기 시작했고(2편의 arXiv 논문), 시장(Anthropic 보고서)이 1년 동안 그 방향으로 더 간다고 본다**.

- **The Last Harness You'll Ever Build (arXiv 2604.21003, 2026-04-22)**: 2-Level 메타 진화. Worker/Evaluator/Evolution 3-에이전트로 `H`를 진화시키는 L1 + 진화 프로토콜 `Λ` 자체를 task 간에 메타-학습하는 L2.
- **Agentic Harness Engineering (arXiv 2604.25850)**: 자동 진화의 빈틈을 **3 observability pillars**(component / experience / decision)가 메운다. **Terminal-Bench 2 pass@1 69.7% → 77.0%** in 10 iterations, 사람이 만든 SOTA harness Codex-CLI(71.9%) 능가.
- **Anthropic 2026 Agentic Coding Trends Report**: 8 트렌드, 3 카테고리. "writing code → orchestrating agents that write code." 60% 사용 / 0–20% fully delegate **격차**가 핵심 데이터 — AI가 빠지는 자리가 아니다.

## 오늘 배운 것 — 핵심 3개

### 1) "Λ"라는 새 개념 — 진화 프로토콜이 학습 가능 객체다

이전까지 위키의 [[concepts/harness-engineering]]는 **`H`(하네스 자체)** 를 설계 대상으로 봤다. Last Harness 논문이 한 단계 위로 올린다 — **`Λ = (W_H, H^(0), V, E)`**, 즉 *"`H`를 어떻게 진화시킬 것인가"* 자체가 학습 객체다. 메타-러닝과의 형식적 대응이 명시.

**위키에 즉시 보강한 것**: [[concepts/harness-engineering]]의 "2026-05-06 보강" 섹션에 2-Level 표 + Λ 정의를 추가했다.

### 2) Decision observability — 우리 위키에 없던 축

DeepEval/LangSmith/Braintrust 등 [[comparisons/agent-eval-frameworks]]에 정리된 6대장은 **결과**를 평가한다. AHE의 **decision observability**는 **edit**을 평가한다 — 모든 변경에 self-declared prediction을 붙이고, 다음 라운드 결과로 검증해 falsifiable contract로 만든다.

**즉효 ROI**: ingest log 항목 한 줄 — *"이 edit이 무엇을 고칠 것이라 주장하는가"*. 이게 곧 우리 위키 작업의 falsifiable contract가 된다. 성공/실패는 다음 ingest의 lint·conflict로 검증된다.

### 3) Anthropic 보고서의 "60% / 0–20% 격차" — 위임 불가능성의 정량

> "Engineers use AI in roughly 60% of their work, but report being able to 'fully delegate' only 0–20% of tasks."

이 두 숫자의 차이가 [[concepts/cognitive-debt]] 의 정량적 근거다. AI가 일을 더 많이 한다는 것은 **사람이 더 많이 검토한다**는 뜻이지, 사람이 빠진다는 뜻이 아니다. Anthropic 자체 데이터로 **Trend 4 (Human oversight scales through intelligent collaboration)** 가 nice-to-have가 아니라 **데이터에서 도출된 결론**임을 못박는다.

또한 AI-assisted work의 약 **27%** 가 그렇지 않으면 안 했을 작업(scaling, dashboards, exploratory) — 생산성이 "더 빠르게"가 아니라 "더 많이"로 나타난다는 정량 데이터.

## 인사이트 — 두 arXiv 논문은 일부러 짝으로 읽어야 한다

| 논문 | 약속 | 빈틈 |
|------|------|------|
| Last Harness (2604.21003) | "자동 하네스 + 메타-진화" | 어떤 신호로 `E`가 옳은 edit을 고르나? |
| AHE (2604.25850) | "3 pillar observability" | 그 관측이 어떻게 자율 루프 안에서 소비되나? |

→ **답이 서로의 빈틈을 메운다**. AHE의 3 pillar는 Last Harness의 `V`·`E`가 신뢰할 수 있는 신호를 받게 만든다. Last Harness의 메타 루프는 AHE의 평가가 task 종속이 아니라 **프로토콜 종속**이 되게 만든다.

## 1인 개발자 즉효 적용 (3가지)

1. **하네스 컴포넌트를 file-level로 분리 유지** — CLAUDE.md, templates/, 프롬프트 스니펫, eval 룰을 각각 작은 파일. revertible성과 attribution이 살아남는다(component observability).
2. **ingest log에 prediction 필드** — 매 edit마다 *"이 edit이 무엇을 고친다고 주장하는가"* 한 줄. 다음 round의 lint/conflict가 검증한다(decision observability).
3. **27% 룰을 인지** — Anthropic 보고서 데이터, AI-assisted work의 27%는 이전엔 안 했을 일. "papercut 픽스"·실험·내부 도구 만들기에 죄책감 갖지 않기.
