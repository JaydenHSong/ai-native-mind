# 2026-05-23 학습 일지 — interface adaptation · terminal provenance · dual-surface tools · branchable sandbox

## 이 글을 읽는 법 (30초)

오늘 4편은 얼핏 보면 각자 다른 층을 다룬다.

- Life-Harness = 모델과 환경 사이 **interface mismatch**
- TerminalWorld = benchmark task가 **어디서 왔는가**
- HarnessAPI = MCP와 HTTP를 **어떻게 한 capability로 묶는가**
- DeltaBox = sandbox를 **얼마나 빨리 되돌릴 수 있는가**

하지만 한 줄로 묶으면 이렇다.

> **agent engineering은 이제 모델 바깥의 interface·runtime·benchmark provenance를 더 정교하게 설계하는 방향으로 간다.**

---

## 1. 오늘 수집한 자료 4편

### 1-A. Life-Harness — interface를 고쳐서 frozen model을 살린다

**한 줄**: "모델이 멍청한 게 아니라, 모델과 환경이 서로 말이 안 통하는 것일 수 있다."

- 논문명: **Adapting the Interface, Not the Model: Runtime Harness Adaptation for Deterministic LLM Agents**
- 핵심 framing:
  - deterministic environment에서 agent failure의 상당수는 **model-environment interface mismatch**
  - solution은 모델 미세조정보다 **runtime harness adaptation**
- Life-Harness intervention 층:
  1. **environment contracts**
  2. **procedural skills**
  3. **action realization**
  4. **trajectory regulation**
- 정량:
  - **7 deterministic environments**
  - **18 model backbones**
  - **126 settings 중 116개 개선**
  - **평균 상대 향상 88.5%**
  - Qwen3-4B에서 진화한 하네스가 **다른 17개 모델로 전이**

### 1-B. TerminalWorld — real terminal workflow provenance를 benchmark로 끌어온다

**한 줄**: "terminal benchmark는 사람이 꾸민 문제집만이 아니라, 실제 녹화에서 다시 뽑아낸 작업 흐름까지 봐야 한다."

- 논문명: **TerminalWorld: Benchmarking Agents on Real-World Terminal Tasks**
- benchmark 생성 방식:
  - **in-the-wild terminal recordings** 를 처리해 task 역구성
- 정량:
  - **80,870 recordings**
  - **1,530 validated tasks**
  - **18 categories**
  - **1,280 unique commands**
  - **200 verified subset**
  - **8 models / 6 agents** 평가
  - 최고 pass rate **62.5%**
  - Terminal-Bench와 상관 **Pearson r = 0.20**
- 핵심 시사점:
  - benchmark score를 읽을 때 task difficulty뿐 아니라 **task provenance** 를 같이 봐야 한다.

### 1-C. HarnessAPI — MCP tool과 HTTP API를 한 skill에서 같이 만든다

**한 줄**: "agent용 MCP와 사람용 HTTP를 따로 유지하지 말고, 같은 skill contract에서 둘 다 파생하자."

- 논문명: **HarnessAPI: A Skill-First Framework for Unified Streaming APIs and MCP Tools**
- 핵심 주장:
  - 같은 business logic가 MCP와 HTTP에서 중복 구현되며 drift가 난다
  - typed skill folder + Pydantic schema를 **single source of truth** 로 둔다
  - 여기서
    - **SSE streaming endpoint**
    - **OpenAPI / Swagger UI**
    - **zero-config MCP tool**
    를 동시에 파생
- 정량:
  - **6 representative skills**
  - 수작업 dual-stack 대비 **framework-facing boilerplate 74% 감소**

### 1-D. DeltaBox — sandbox는 보안 장치이자 search 가속기다

**한 줄**: "샌드박스를 빨리 되돌릴 수 있어야 long-horizon agent가 여러 시도를 깊게 탐색할 수 있다."

- 논문명: **DeltaBox: Scaling Stateful AI Agents with Millisecond-Level Sandbox Checkpoint/Rollback**
- 핵심 기여:
  - full copy 대신 **change-based checkpoint/rollback**
  - **DeltaFS**: layered filesystem + copy-on-write
  - **DeltaCR**: incremental process-state dump + template-based restore
- 정량:
  - checkpoint **14ms**
  - rollback **5ms**
- 핵심 시사점:
  - sandbox는 단순 격리 방이 아니라 **branchable runtime substrate** 다.

## 2. 오늘의 연결 그림

| 층 | 오늘 소스 | 새로 선명해진 질문 |
|---|---|---|
| **environment interface** | Life-Harness | 실패 원인이 모델이 아니라 interface mismatch일 때, 하네스는 어디를 고쳐야 하는가? |
| **benchmark provenance** | TerminalWorld | 이 benchmark task는 실제 workflow에서 왔는가, 아니면 사람이 꾸민 synthetic set인가? |
| **capability deployment** | HarnessAPI | 같은 tool capability를 MCP와 HTTP에 중복 없이 어떻게 노출할 것인가? |
| **runtime branching** | DeltaBox | agent가 여러 시도를 빠르게 되감고 분기하려면 sandbox는 어떤 성질을 가져야 하는가? |

어제([[journal/2026-05-22]])가 **substrate / scale boundary / disclosure metadata** 를 강조했다면, 오늘은 그 substrate를 실제로 구성하는 더 세밀한 운영 단위가 보였다.

1. **interface** 를 고치는 하네스
2. **benchmark provenance** 를 따지는 eval
3. **dual-surface capability** 를 만드는 tooling
4. **branchable state runtime** 으로서의 sandbox

## 3. 기존 지식과의 연결 포인트

### 3-A. Harness Engineering은 이제 policy보다 interface 쪽으로도 내려간다

최근 하네스 논의는 아래처럼 쌓여 있었다.

- NLAH / CLAUDE.md = policy representation
- AHE / Insights Generator = observability-driven evolution
- Library Drift = skill lifecycle governance
- Code as Agent Harness = code substrate 상위 프레임

오늘 Life-Harness가 들어오면서 하네스의 질문이 하나 더 생겼다.

- **모델과 환경이 서로 어떤 규약으로 맞물리는가?**

즉 하네스는 단순 제약과 검증 장치가 아니라 **interface translation layer** 이기도 하다.

### 3-B. Eval은 environment realism 다음에 benchmark provenance 층이 붙었다

기존 eval 축은 대략 이랬다.

- judge reliability = JRH
- run disclosure = Benchmark Disclosure Audit
- surface vs truth = SpecBench / ResearchArena
- process controllability = ProcBench / HarnessAudit
- environment realism = WildClawBench

오늘 TerminalWorld가 들어오면서 다음 질문이 생긴다.

- **이 task 자체가 현실 workflow에서 왔는가?**

즉 이제는 environment realism만이 아니라 **benchmark provenance** 를 봐야 한다.

### 3-C. Tool Use는 schema를 넘어 deployment artifact가 된다

SkillSmith와 Formal Skill이 이미 tool/skill을 runtime interface·capability object 쪽으로 끌고 갔다면, HarnessAPI는 거기서 한 걸음 더 나아가

- 같은 capability를
- **HTTP surface** 와
- **MCP surface**

로 동시에 내보내는 deployment 문제를 정면으로 다룬다.

즉 tool definition은 이제 prompt용 설명서가 아니라 **운영 surface를 여러 개 가진 capability registry** 로 읽어야 한다.

### 3-D. Sandbox는 안전 문제이면서 search 문제다

기존 safe-tool-calling 관점에서는 sandbox가 주로 보안 방어선이었다. 오늘 DeltaBox가 들어오면서 질문이 바뀐다.

- 얼마나 안전하게 가둘 수 있는가?
- 얼마나 빨리 되돌리고 다시 시도할 수 있는가?

즉 sandbox는 security primitive이자 **throughput primitive** 다.

## 5. 핵심 배움

1. **하네스는 모델을 감싸는 정책층일 뿐 아니라, 모델과 환경이 맞물리는 interface layer다.**
2. **deterministic domain에서는 모델 업그레이드보다 interface adaptation이 더 큰 수확을 줄 수 있다.**
3. **real-world agent eval은 environment realism만으로 부족하고 benchmark provenance까지 봐야 한다.**
4. **tool capability는 MCP와 HTTP를 따로 관리할수록 drift가 생기므로 single-source deployment가 중요하다.**
5. **sandbox는 안전장치이자 branch exploration 인프라다. reset latency가 agent throughput을 좌우할 수 있다.**
6. **trajectory log는 단순 디버그 기록이 아니라 하네스 개입 규칙을 학습하는 재료가 될 수 있다.**
