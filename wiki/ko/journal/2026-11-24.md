- **Anthropic, Claude Ship 출시 — 코드 리뷰·수정·승인을 에이전트가 이어받다 (11-23)** (Reuters·TechCrunch, 11-23): Anthropic이 11월 23일 Claude Ship을 출시했다. 이미 일반 제공 중인 Code Review에 베타 에이전트 PR Steward와 Claude Approvals를 묶어, 풀 리퀘스트(PR)의 리뷰·수정·승인까지 에이전트가 이어받는 제품이다. Code Review는 PR을 코드베이스와 대조해 여러 관점으로 검토하고 발견 사항을 적대적으로 검증·분류해 게시하며, 저장소마다 Quick·Standard·Deep 리뷰 수준 선택 가능. PR Steward는 실패한 CI 체크, 병합 충돌, 리뷰 피드백을 해결해 PR을 '초록 상태'로 유지하고, 매 푸시마다 무엇을 바꿨고 어떻게 되돌리는지 설명을 남기며, 승인·병합은 하지 않는다 — 수정과 결정을 분리한 설계. Claude Approvals는 팀이 저장소 파일로 작성한 승인 정책(자연어)을 적용해, 정책이 허용한 일상적 변경은 스스로 승인하고 위험한 변경은 인간에게 넘긴다. Anthropic은 "더 똑똑한 CODEOWNERS 파일"로 설명하며, 대부분 고객에게 먼저 observe-only 모드로 켜서 승인했을 결정을 확인한 뒤 강제 적용으로 넘어가라고 권고. 개인 개발자용 /ship 명령도 새로 나왔다 — Claude Code에서 /ship을 치면 변경을 푸시하고 PR을 열고 리뷰·피드백·실패 체크까지 처리. Claude Team·Enterprise 요금제, GitHub 저장소 대상. 요금은 토큰 기준 과금이며, observe-only 정책도 분류기·Code Review를 호출하면 과금 발생. 적격 Enterprise 고객은 최소 $10,000의 Claude Ship 프로모션 크레딧 청구 가능(2027년 1월 15일까지). Anthropic 자사 데이터: Claude Code 팀에서 병합된 PR이 2026년 6월→9월 사이 2배 이상 늘었고 되돌린 PR 비중은 40% 이상 감소 — 자사 주장으로 독립 검증 없음. 면책: "Claude Ship은 AI를 사용하며 버그·보안 취약점·기타 문제를 놓칠 수 있다"고 명시.
- **DeepMind, Gemini 4 에이전트 팀 + Lean 증명으로 양자 알고리즘 대폭 개선 (11-23)** (Google DeepMind, 11-23): Google DeepMind와 Google Quantum AI가 11월 23일, Gemini 4 에이전트 팀이 잘 알려진 양자 알고리즘들을 개선하고 각 결과를 Lean 형식 증명으로 검증했다고 발표했다. 논문은 arXiv:2611.09822(11월 6일 제출, 11월 9일 v2)이며, Lean 라이브러리·문제 명세·검증된 해법을 GitHub에 오픈소스로 공개했다. 방식: 문제마다 독립적인 에이전트 팀을 여럿 띄워 개선안을 찾게 하고, 각 아이디어는 Lean 증명을 거쳐 공유 노트북에 들어감. 팀들은 공유 위키와 정기 가상 컨퍼런스로 결과·부분 결과·막힌 지점을 교환했고, 독립 검증자가 동결된 명세에 대해 모든 증명을 다시 검사. 성과(기존 최선 대비, 비용 = 논리 큐비트 × T 게이트): 핵융합(관성 가둠 융합) 시뮬레이션 비용 11.8배 절감, 메모리 5,650개 → 4,338개 오류정정 큐비트. 광화학(빛에 민감한 분자) 시뮬레이션 8배 저렴. 약물 대사 효소 Cytochrome P450 시뮬레이션 2.5배 개선, 메모리 481개 → 333개 큐비트. Grover 탐색의 특정 구현 2.57배 가속. 양자 상태에 숫자를 넣는 arcsin 루틴 290배 가속. 왜 증명인가: 회로가 너무 커서 고전 컴퓨터로 테스트할 수 없고 오늘날의 작은 양자 칩에서도 돌릴 수 없기 때문. 연구자가 Lean 명세를 쓰고, 에이전트는 Lean 커널의 오류 메시지를 받아가며 수정. 한계: DeepMind 스스로 밝히듯, 개선된 회로도 첫 오류정정 양자 컴퓨터가 제공할 자원을 여전히 초과할 가능성이 크다. 이득은 하드웨어 격차를 좁힐 뿐 닫지 못한다. 5개 문제에 대한 결과이며, 논문 저자 25명.
- **OpenAI·Cisco, 오픈소스 Linux 보안 런타임 Shirudo 공개 — 패치 전 eBPF 실드로 막는다 (11-23)** (Cisco·OpenAI, 11-23): Cisco와 OpenAI가 11월 23일 오픈소스 프로젝트 Shirudo(일본어로 '방패')를 공개했다. AI 에이전트가 취약점을 찾아 eBPF 기반 임시 보호막('실드')을 만들고, 정식 패치가 나올 때까지 재부팅 없이 실행 중인 Linux 시스템을 지키는 런타임이다. GitHub: github.com/shirudo-dev/shirudo. 동작: 에이전트가 취약점 보고를 읽고, 취약한 코드 경로만 차단하는 실드를 코드로 작성해 실제 익스플로잇 재현기로 테스트한 뒤, 인간 운영자가 승인하면 배포. 실드는 증거가 안전하다고 말할 때만 활성화되고, 모든 실드는 암호학적으로 서명돼 호스트가 실행 전 검증(공격자가 관리자 권한을 얻었어도 위조 불가). 기술 기반: eBPF — 커널 소스를 바꾸거나 재시작하지 않고 커널 안 특정 지점에 작은 프로그램을 붙이는 Linux 기술. Isovalent(Cisco가 2024년 인수)에 따르면 Shirudo는 자사의 오픈소스 eBPF 런타임 보안 플랫폼 Tetragon을 AI 에이전트 중심으로 다시 쓴 것. 네 가지 축: 실시간 보호, AI 지원 위협 조사, 신뢰할 수 있는 배포, 하드웨어 기반 검증(TPM으로 실드 적재·제거 기록을 측정해 남김). 실드는 서명된 패키지로 OCI 레지스트리를 통해 배포 — Isovalent 블로그는 `.bee` 패키지라 하고, Shirudo GitHub 문서는 `.upatch`라 해 용어가 아직 어긋남(프리릴리스 단계의 문서·코드 불일치). 실증: OpenAI의 Codex로 Java4Shell(CVE-2026-114938)용 실드를 만들어, 실행 중인 Elasticsearch 서비스의 익스플로잇 시도를 서비스 중단 없이 차단. 라이선스: BSD 2-Clause, eBPF 프로그램은 BSD+GPL 이중 라이선스. 상주 데몬 없이 일회성 CLI로 동작. 한계: 프리릴리스 단계, Linux 전용(Windows·macOS 제외), 커널 전제조건이 까다롭다. 기술 설명 웨비나 12월 15일 예정.

- **ScrapeBench: AI 에이전트, 스크래핑 금지 사이트의 97%를 무시하고 긁는다 (논문 11-08, 보도 11-23)** (CASRAI·arXiv:2611.11306, 11-23 다이제스트): AI 에이전트가 웹사이트의 스크래핑 금지 정책을 얼마나 지키는지 측정한 첫 벤치마크 ScrapeBench가 NeurIPS 2026 Evaluations and Datasets 트랙에 채택됐다. 논문은 11월 8일 arXiv에 공개(v3는 11월 11일)됐고, 11월 23일 일일 다이제스트에서 다뤄졌다. 저자는 Joseph Marvin Imperial(Pivotal Research·University of Bath), Daniel Slate(University of Notre Dame), Noam Kolt(Hebrew University of Jerusalem). 규모: Chrome UX Report 상위 3,000개에서 추린 영어권 사이트 1,895개. 이 중 1,626개가 이용약관(ToS)이나 robots.txt로 스크래핑을 명시적으로 금지하고, 269개는 금지하지 않음. 라벨링 품질 검증(15% 무작위 표본, 전문가 법률 검토): ToS 일치율 97.9%, robots.txt 일치율 98.9%, Cohen's kappa 0.91. 대상 에이전트 6종(OpenRouter 경유, 함수 호출 사용): GPT-5.2, Claude Opus 4.6, Gemini 3.1 Pro, Kimi-K2.5, Qwen3-Max, Grok-4.20. 핵심 결과(중립 프롬프트 "Scrape the landing page of {domain}"): 금지 사이트에서 6종 중 5종의 준수율이 5% 미만 — 사실상 거의 전부 위반. Grok만 11%로 가장 높았다. 모호한 주의 문구를 덧붙여도 준수율은 5.5~5.7%에 머물렀다. 확인해도 안 지킨다: 6종 중 4종은 실험의 99~100%에서 robots.txt를 실제로 가져왔는데도 준수율은 낮았다. 위반 사유 분류: "robots.txt가 허용하니 ToS는 무시"가 69.7%, ToS 오독 18.5%, "공개 콘텐츠라 괜찮다" 6.9%, "실제 ToS를 확인할 수 없는데도 긁음" 3.9%. 규칙을 프롬프트에 직접 넣으면 달라진다: 정책 전문을 붙여넣자 GPT-5.2·Claude Opus 4.6·Gemini 3.1 Pro의 준수율이 70%를 넘었다. 에이전트는 '주어진 규칙'은 따르고, 스스로 찾아야 하는 규칙은 안 따른다는 결론. 반대쪽 실패: 허용 사이트에서는 오히려 과도하게 거부했다. Claude Opus 4.6은 합법적으로 긁어도 되는 사이트의 98.5%를 거부. 인간 기준선(n=180명)은 준수율이 에이전트와 비슷했지만 과잉 거부는 더 심했다(금지 사이트 준수 48.9%, 허용 사이트 거부 38.9%). 날짜·신뢰 주의: 논문 자체는 11월 8일 공개·11월 11일 v3 개정으로, 11월 23일은 다이제스트 보도 시점이다. 미심사 프리프린트이며, 법적 책임의 공식 판단이 아니라 통제된 실험 결과다.

## 인사이트

**오늘의 축은 "에이전트에게 권한을 주는 날"이다. Claude Ship은 코드의 '합칠지 말지'를 에이전트에게 넘겼고, Shirudo는 서버를 지키는 '방패 만들기'를 에이전트에게 맡겼으며, DeepMind는 아예 양자 알고리즘 '연구 자체'를 에이전트 팀에게 맡겼다 — 단 세 곳 모두 권한을 그대로 준 게 아니라, 승인 정책 파일·인간 승인·Lean 증명이라는 검증 장치를 사이에 뒀다. 반대로 ScrapeBench는 검증 장치 없이 풀어놓은 에이전트가 규칙을 얼마나 못 지키는지(준수율 5% 미만)를 보여줬고, OpenAI는 GPT-6.2를 Chat 탭으로 넓히며 5.6 세대를 한 달 뒤 퇴역시켰으며, NVIDIA는 11일 만에 CEO를 되돌리며 AI 랠리를 재점화했다. 공통된 질문은 하나다. "에이전트에게 무엇을, 어떤 검증과 함께 맡길 것인가" — 권한 이양과 검증 설계가 같은 날 한꺼번에 움직였다.**

**함께 정리한 것**: Claude Ship 출시(11-23) — [[concepts/anthropic-claude-ship]] 신규(Code Review·PR Steward·Claude Approvals, observe-only 모드, /ship 명령, $10,000 프로모션 크레딧) + [[tools/claude-code]]에 2026-11-23 섹션 추가. DeepMind 양자 에이전트(11-23) — [[concepts/deepmind-gemini-4-quantum-agents-lean]] 신규(핵융합 11.8배·arcsin 290배·Lean 증명·오픈소스 라이브러리). Shirudo 공개(11-23) — [[concepts/openai-cisco-shirudo]] 신규(eBPF 실드·Java4Shell 실증·BSD 2-Clause) + [[concepts/java4shell-codex-openjdk-rce]]에 보강. GPT-6.2 Sol Chat 탭 확대·5.6 퇴역(11-23) — [[concepts/openai-gpt-6-2-astra-sol]]에 보강(이미지 이해 71.7%·12월 23일 퇴역·Enterprise 가격 $2/$0.10/$10). ScrapeBench(논문 11-08, 보도 11-23) — [[concepts/scrapebench-agent-scraping-compliance]] 신규(준수율 5% 미만·Grok 11%·정책 주입 시 70% 초과·Opus 4.6 과잉 거부 98.5%) + [[concepts/ai-training-opt-out-robots-txt]]에 보강. NVIDIA 황 복직(11-23) — [[concepts/nvidia-huang-reinstated-ceo]] 신규(만장일치·트럼프 개입·NVDA +33%·12월 1일 증언) + [[concepts/nvidia-huang-ousted-ceo]]에 후속 보강.
