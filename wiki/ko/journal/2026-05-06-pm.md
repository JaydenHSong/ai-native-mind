# 2026-05-06 PM 학습 일지 — 수요 데일리 후속 (오후 보충 인제스트)

## 이 글을 읽는 법 (30초)

오전 인제스트([[journal/2026-05-06]])는 **자동 진화 + 관측**의 같은 라인 3편(Last Harness · AHE · Anthropic 트렌드 보고서)을 다뤘다. 오후는 **그 라인 외부**의 세 좌표축을 채운다 — 같은 시점 arXiv에 떠 있던 세 논문이 서로 다른 질문에 답한다.

| 좌표축 | 질문 | 논문 |
|--------|------|------|
| **Descriptive** | 실제 70개 프로젝트는 어떻게 생겼나? | [Wei, "Architectural Design Decisions in AI Agent Harnesses" (arXiv 2604.18071)](https://arxiv.org/abs/2604.18071) |
| **Prescriptive** | 안전-크리티컬에서 LLM의 sycophantic compliance를 어떻게 막나? | [Zhang, "Harness as an Asset: CAAF" (arXiv 2604.17025)](https://arxiv.org/abs/2604.17025) |

## 한 그림으로 잇기 (오전 + 오후 = 1년 지도)

```
(오전) "H는 변수다"          (오전) "Λ가 무너지지 않게"      (오후) "지도 그리기"
Last Harness (L1+L2)    ── AHE (3 pillars) ─────────── Wei 5 dimensions
        │                         │                              │
        ▼                         ▼                              ▼
(오후) "코드로 구현"        (오후) "잠가서 강제"
Meta-Harness            ── CAAF (UAI + locking)
(filesystem proposer)      (anti-evolution: H는 asset)
```

**핵심 통찰**: 자동 진화 라인(상단)과 결정적 잠금 라인(하단)은 *직교*한다. "H를 똑똑하게 만든다" vs "H를 신뢰 가능하게 만든다". 안전-크리티컬에서는 둘이 합쳐져야 한다 — 진화된 `H`도 UAI로 잠긴 invariant를 통과해야 한다.

## 오후 배운 것 — 핵심 3개

### 1) 70 프로젝트 corpus가 보여 주는 *현재 위치* (Wei)

CLI 프레임워크와 멀티-에이전트 오케스트레이터가 생기는 5축이 있고, 우리 위키도 거기서 자유롭지 않다.

| Dimension | corpus modal | 우리 위키의 갭 |
|-----------|--------------|----------------|
| Subagent Architecture | none → multi-level | [[patterns/subagents-delegation]] 있음, hierarchy depth 정량 비교 미흡 |
| Context Management | **file-persistent hybrid 27.1%** | [[concepts/ai-memory-systems]] 있음, file-persistent 패턴 별도 페이지 부재 |
| Tool Systems | **registry 34.3% > MCP 14.3%** | [[concepts/mcp]]가 "emerging"임을 정량 확인 |
| Safety Mechanisms | container ↔ structured approval lift 3.4 | [[concepts/agent-supply-chain-security]]에 격리·승인 짝 매핑 추가 가능 |
| Orchestration | imperative > declarative > event-driven | [[concepts/ai-orchestration]] 6 패턴이 imperative 중심 |

**1인 함의**: registry가 아직 dominant이고 MCP가 emerging이다 → 자체 도구는 registry 패턴으로 충분, MCP는 cross-system 공유가 필요할 때만 들어간다는 결정이 정량적으로 정당화된다.

### 2) `H = Asset`이라는 framing 전환 (CAAF)

Zhang의 CAAF는 자동 진화 라인의 *반대* 답이다 — **`H`를 진화시키지 마라, asset으로 잠가라**.

| | Last Harness | CAAF |
|---|--------------|------|
| What evolves | `H`와 `Λ` 둘 다 | nothing — `H`는 검증된 invariant |
| When | offline meta-learning | inference-time enforcement |
| 비유 | "더 나은 컴파일러를 학습" | "타입 시스템이 거짓말 못 하게" |

핵심 메커니즘 4개: **RAD**(physical isolation + context firewall), **HaaA**(YAML constraint registry), **UAI**(Python assertion engine, LLM override 불가), **State Locking**(PASS된 schema read_only).

정량 충격:
- **L3 자율주행 paradox detection**: CAAF-GPT-4o-mini **30/30** vs monolithic GPT-4o no-hint **0/30**
- **Pharmaceutical 7-constraint nonlinear paradox**: CAAF **20/20** vs monolithic mini no-hint **0%**
- **Multi-agent baseline 80 trial 0%** — debate, sequential checker 모두 실패. 오케스트레이션만으로는 reliability gap이 닫히지 않는다는 *두 번째 정량 근거*(첫 번째: Google 2026-05-02 17.2x vs 4.4x)

**1인 함의**: 우리 `CLAUDE.md`·`templates/`·frontmatter 스키마가 **이미 mini-UAI**다. Lint 워크플로우의 deterministic PASS/FAIL은 CAAF의 UAI와 동형이다. State Locking을 ingest 워크플로우에 내장하면 단계 건너뛰기/oscillation이 사라진다 — [[patterns/bkit-superpowers-combo]]의 다음 진화 단계.

### 3) Meta-Harness의 filesystem-as-memory 패턴이 LLM-Wiki와 동형이다 (Lee et al.)

Stanford 팀의 Meta-Harness는 자동 하네스 진화의 **실제 구현 paths**를 제시한다. proposer가 raw LLM이 아니라 **coding agent**라서 grep/cat으로 prior 후보의 source code·trace·score를 *선택적으로* inspect.

| 비교 차원 | 기존 text optimizer | Meta-Harness |
|-----------|---------------------|--------------|
| MTok/iter | 0.002–0.026 | **10.0** (3 orders of magnitude up) |
| History | window/last/summary | **full filesystem** |
| Proposer | LLM with prompted context | **agentic** (grep, cat, file ops) |

벤치마크: 텍스트 분류 ACE 대비 **+7.7 points, 4× fewer context tokens**, 60 proposal → 4 evaluation으로 동일 정확도 도달; IMO-level math 5 모델 평균 **+4.7 points**; **TerminalBench-2 #1 (Haiku 4.5 부문)**.

**1인 함의 — 우리 위키 자체가 Meta-Harness의 filesystem이다**:

```
Meta-Harness                     ai-native-mind wiki
─────────────                    ────────────────────
prior candidate dirs   ←→        wiki/concepts/, wiki/patterns/, ...
execution traces       ←→        wiki/log.md
scores (eval results)  ←→        frontmatter confidence/status
agentic proposer       ←→        Claude Code (이 세션)
filesystem ops         ←→        grep, Read, Edit
```

Meta-Harness가 코드 영역에서 한 일을 우리는 **개념 위키에서 이미 하고 있다**. Anthropic Cowork(daily-briefing/candidate-analysis 스킬도 같은 패턴)가 같은 추상화를 OS 레벨로 끌어올린 것 — 자동 진화의 인프라는 *파일시스템*이다.
