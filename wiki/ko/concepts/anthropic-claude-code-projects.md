# Anthropic Claude Projects 재설계 — 코디네이터가 병렬 스레드 세션 조율 (11-14)

## 쉽게 읽기

**비유**: 학급 프로젝트에서 반장(코디네이터)이 일을 나눠주고, 조원(스레드)들이 각자 다른 책상(브랜치)에서 일한 뒤 결과를 모아오는 방식이다. 예전 Projects가 파일을 모아두는 서랍이었다면, 이제는 일을 시키고 받아오는 팀장이 딸린 작업실이 됐다.

| 용어 | 풀이 |
| **코디네이터** | 목표를 받아 일을 나누고, 스레드들의 결과를 검토·합치는 지휘 세션 |
| **스레드(thread)** | 하나의 일을 맡아 도는 Claude Code 클라우드 세션. 자기 브랜치와 저장소 복사본에서 일한다 |
| **클라우드 세션** | 내 컴퓨터가 아니라 Anthropic 서버 위에서 도는 작업 세션 |
| **서브에이전트** | 스레드 안에서 일을 더 쪼개 맡기는 하위 에이전트 |
| **머지 충돌** | 두 사람이 같은 코드를 다르게 바꿨을 때 생기는 겹침. PR에서 직접 해결한다 |
| **노력(effort) 수준** | 모델이 한 작업에 얼마나 깊이 파고들지를 정하는 설정 |

## 한줄 정의

2026-11-14 — Anthropic이 Claude Projects를 파일 폴더에서 조율된 작업 세션 집합으로 재설계했다. 사용자가 목표를 적으면 코디네이터 Claude가 범위를 정하고 병렬 스레드에 일을 나눠주고 결과를 검토·합친다. 휴대폰에서도 진행을 조율할 수 있고, 사용자가 자리를 비워도 작업이 계속된다.

## 핵심 내용

- **구조**: 프로젝트는 "일을 하는 스레드와 이를 지휘하는 코디네이터"로 구성된다. 각 스레드는 자기 브랜치와 저장소 복사본에서 도는 Claude Code 클라우드 세션이다. 스레드는 필요하면 서브에이전트·루프·워크플로우로 자기 일을 더 쪼갤 수 있다. 두 스레드가 같은 코드를 건드리면 겹침은 일반 PR의 머지 충돌로 드러난다.
- **동작**: 코디네이터가 요청 범위를 정하고 작업을 위임·조율·검토해 최종 결과를 합친다. 저장소가 연결되면 스레드가 PR을 열고 테스트를 돌리고, 문서면 읽고 초안을 쓴다. 모든 스레드는 공유 메모리에 기여하고 거기서 가져가며, 프로젝트 라이브러리가 사용자가 올린 파일과 Claude가 만든 산출물을 모은다. 체크인 빈도·새 스레드 시작 빈도·업데이트 상세도를 사용자가 조절할 수 있다.
- **출시 범위**: 오늘부터 Claude Code 클라우드 세션을 쓰고 웹·데스크톱에 기존 프로젝트가 없는 일부 Pro·Max 구독자에게 베타로 제공된다. 다음 주에 같은 요금제의 Claude Code 사용자로 확대하고, 이후 Claude 전체와 Team·Enterprise 요금제로 넓힌다. 기존 프로젝트는 그대로 동작하고 롤아웃이 닿으면 업그레이드된다. 접근이 없으면 대기자 명단(claude.com/form/projects)에 등록한다.
- **비용·한계**: 프로젝트가 여러 스레드를 동시에 돌리면 각 스레드가 온전한 Claude Code 세션이라 사용량 한도에 더 빨리 도달한다. 프로젝트별 사용량을 확인하고 코디네이터 채팅과 워커 스레드의 모델·노력 수준을 각각 고를 수 있다. 보도에 따르면 하루 신규 스레드 200개 상한이 있다(AlphaSignal 인용). 스레드는 지금은 클라우드에서만 돌고, 로컬 머신에서 내 도구·코드·네트워크 안에서 도는 기능은 "곧" 온다고 한다.
- **예시**: 체크아웃 p75 지연을 줄이겠다는 목표를 주면 각 엔드포인트 프로파일링·최적화 테스트·PR 열기를 병렬 스레드로 수행한다. API·웹·모바일 저장소를 연결하고 구식 v1 엔드포인트 은퇴를 지시하면 저장소마다 스레드를 만들어 호출자를 이전하고 테스트를 돌린 뒤 어떤 PR부터 합쳐야 하는지 알려준다.

## 왜 중요한가 (1인 개발자 관점)

1. **오케스트레이션이 제품이 됐다**: 내가 하네스로 짜던 "코디네이터가 일을 나누고 합친다"는 패턴이 Claude Code의 기본 기능이 됐다. 1인 개발자의 경쟁력은 이제 하네스 자체가 아니라, 어떤 목표를 어떻게 쪼개서 맡기는지에 달렸다.
2. **긴 작업의 단위가 "대화"에서 "프로젝트"로 바뀌었다**: 며칠 걸리는 일을 한 번 지시하고, 휴대폰으로 중간 점검만 하면 된다. 내 개발 루틴에서 "지시-점검-합치기"의 리듬이 바뀐다.
3. **비용 구조를 먼저 봐야 한다**: 스레드 하나가 세션 하나라, 병렬로 벌릴수록 사용량이 그대로 곱해진다. 큰 작업을 맡기기 전에 모델·노력 수준을 낮춰서 시범 운영하는 게 싸다.

## 한계 (명시)

- 베타가 좁다. 오늘 접근 가능한 건 클라우드 세션을 쓰는 일부 Pro·Max 구독자 중 기존 프로젝트가 없는 사람뿐이다. Team·Enterprise는 아직 뒤에 있다.
- 스레드는 클라우드에서만 돈다. 로컬 머신·내 네트워크 안에서의 실행은 아직 예고 단계다.
- 하루 신규 스레드 200개 상한은 보도 인용(AlphaSignal)이라 Anthropic 공식 문서에서 재확인해야 한다.
- Anthropic의 'Worse Together' 연구가 보여주듯, 멀티 에이전트 팀은 코디네이터가 약하면 단일 세션보다 못해질 수 있다. 코디네이터의 품질이 성패를 가른다.
