# Anthropic 통합 Claude Enterprise 출시 — 11-16 기본 켜짐

## 쉽게 읽기

**비유**: 지금까지는 '가벼운 질문용 창구'와 '무거운 작업용 작업실'이 따로 있었다. 이제는 창구에서 말을 걸면, 무거운 일이 생길 때 알아서 뒤편 작업실(클라우드 컴퓨터)로 넘어갔다가 결과를 들고 돌아온다. 손님은 창구를 고를 필요가 없어졌다. 다만, 기업은 11-16에 자동으로 이 방식이 켜지니, 그 전에 "우리 데이터는 작업실에 못 보낸다"고 정해둘 수 있다.

| 용어 | 풀이 |
|------|------|
| **격리 클라우드 샌드박스** | 작업마다 따로 배정되는, 외부와 분리된 클라우드 가상 컴퓨터 |
| **Efficient 모드** | 비용 관리를 위해 사용 모델을 Sonnet·Haiku로 제한하는 설정 |

## 한줄 정의

2026-10-23 Anthropic이 Enterprise 고객에 정식 출시한 통합 Claude — 채팅으로 시작해 코드·파일 작업이 필요하면 격리 클라우드 샌드박스의 Cowork 세션으로 전환됐다가 돌아오는 구조, 기존 조직은 11-16 기본 켜짐.

## 핵심 내용

- **동작 방식**: "모든 대화는 채팅으로 시작하고, 작업에 코드 실행이나 파일 작업이 필요하면 같은 대화가 Anthropic 관리 격리 클라우드 샌드박스에서 이어진 뒤, 완성된 작업을 검토용으로 반환한다." 모드를 미리 고를 필요 없음. 웹·데스크톱·모바일에서 이어지고, 노트북을 닫아도 클라우드 작업은 계속됨.
- **전환 일정**: 기존 조직은 기본 꺼짐, 11-16 기본 켜짐(관리자가 유지 거부 가능). 조기 활성화도 가능. 채팅과 클라우드 코드 실행이 모두 켜져 있어야 동작.
- **격리·권한 설계**: 에이전트 대화마다 격리 가상머신. Enterprise는 샌드박스 네트워크 접근 기본 차단, 커넥터 자격증명은 샌드박스 밖에 유지. 기존 SSO·컴플라이언스 API 등 기업 통제 유지. 기존 채팅·프로젝트·커넥터·스킬·플러그인 이관.
- **비용 통제**: 사용량 기반 과금 유지. 신규 Efficient 모드는 통합 경험을 Sonnet·Haiku 모델로 제한해 지출 관리 — 조직·그룹·개인별 한도와 병행.
- **제외 범위**: 제로 데이터 보존·HIPAA 대응 구성·고객 관리 암호화 키(CMEK) 조직은 현행 설정 유지, 통합 대상 제외.
- **연계 일정**: 9-16 Pro·Max 통합 시작 → 10-23 Enterprise GA. 같은 주간의 Duet(10-21 연구 프리뷰)과 함께 '상시·클라우드 에이전트' 라인업 확장 국면.

## 왜 중요한가 (1인 개발자 관점)

1. **에이전트 실행 위치의 이동**: 작업이 내 컴퓨터가 아니라 공급자 클라우드에서 돌아간다는 점 — 실행 위치가 곧 보안·비용·지속성의 경계가 됨.
2. **기본값 전환의 무게**: 11-16 기본 켜짐은 '선택'이 아니라 '거부해야 하는' 전환 — 기업 에이전트 도입에서 기본값 날짜가 곧 정책 결정일.
3. **대화-작업 경계의 소멸**: 채팅과 에이전트 작업의 구분이 사라지면, 승인 게이트(무엇을 혼자 하고 무엇을 물어볼지)가 대화 안에 녹아들어야 함.

## 한계 (명시)

- 통합 대상 제외 조직(제로 보존·HIPAA·CMEK)은 현행 유지 — '모든 Enterprise'가 아니라는 경계 명시 필요.
- 샌드박스 네트워크 기본 차단이지만 커넥터별 실제 egress 정책은 조직 설정에 따라 달라짐.
- 가격(사용량 과금)의 실제 단가는 미공개 — Efficient 모드의 절감 폭은 정량화되지 않음.
