# OpenAI 'Research acceleration: The jagged frontier' — 코딩 에이전트, 2~4시간 과제 무개입 성공률 46%

## 쉽게 읽기

**비유**: OpenAI가 자기 회사 연구원들의 일하는 방식을 재봤다. 코딩 AI에게 2~4시간짜리 일을 맡기면, 이제 절반 가까이(46%)는 사람 손을 하나도 안 대고 끝낸다. 3월에는 4번 중 1번꼴이었다. 그런데 일의 종류마다 편차가 크다 — "돌아가는 실험 지켜보기"는 79%나 성공하는데 "서버 코드 새로 짜기"는 25%뿐이다. 잘하는 일과 못하는 일의 경계가 울퉁불퉁하다는 뜻이다.

| 용어 | 풀이 |
|------|------|
| **무개입 성공률** | 사람이 중간에 손대지 않고 에이전트가 일을 끝까지 마친 비율 |
| **재귀적 자기개선(RSI)** | AI가 차세대 AI를 만드는 데 쓰이면서 스스로를 점점 더 빨리 발전시키는 과정 |
| **작업일(agent workday)** | 에이전트가 하루에 한 일의 양을 사람 하루 일로 환산한 단위 |
| **에이전트** | 목표를 주고 맡기면 스스로 계획하고 도구를 써서 일하는 AI |

## 한줄 정의

OpenAI가 2026년 11월 18일 공개한 두 번째 연구 가속 보고서 **"Research acceleration: The jagged frontier"**에 따르면, 자사 코딩 에이전트는 인간 기준 2~4시간짜리 연구 과제를 사람 개입 없이 완수하는 비율이 2026년 3월 23%에서 10월 46%로 두 배가 됐다. 다만 과제 종류별 편차가 커서 OpenAI 스스로 경계를 "울퉁불퉁한(jagged)" 전선이라고 불렀다. 9월 첫 보고서의 후속이다.

## 핵심 내용

- **핵심 지표(무개입 성공률)**: 사람이 개입하지 않고 에이전트가 위임받은 과제를 끝낸 비율. 2~4시간 과제 23% → 46%(3월→10월), 4~8시간 과제 13% → 35%.
- **과제별 편차(2026-08-01~10-18)**: 학습 실행 모니터링 79%, 기술 질문 답변 72%, 소통 69%, 분석 58%, 구축 43%, 학습 실행 시작 35%, 평가·강화학습 환경 구축 29%, 추론·서빙 스택 코드 작성 25%. 약한 분야가 전체 연구 가속의 병목이 될 수 있다고 OpenAI는 경고했다.
- **사용 규모**: 연구원 1인당 하루 에이전트 지출 중앙값(API 정가 환산) 약 $2,400(10월), 9월 대비 +62%. 상위 10%는 약 $23,000(+105%). 연구원 1인당 하루 평균 에이전트 작업일 수는 0.5일에서 5.7일로 약 11배 늘었다. 10월 중순 기준 연구원의 3분의 2 이상이 하루에 4개 이상의 에이전트를 동시에 돌렸다.
- **설문(101명, 8월 말~9월 초)**: GPT-5.2를 넘는 코딩 에이전트를 3개월간 못 쓰게 된다면, 중앙값 응답자는 팀 인원의 40%나 팀 컴퓨팅 자원의 30%를 내주고서라도 되찾겠다고 답했다. Safety & Alignment 분야의 문서화된 연구 작업주(workweek)는 1월→9월 77% 늘며 전 분야 중 절대 증가폭 최대였다.
- **정책 맥락**: 보고서의 명시적 목적은 재귀적 자기개선(RSI, AI가 차세대 AI 개발을 가속하는 과정)과 관련한 지표를 추적하는 것이다. OpenAI는 9월 보고서에 이어 모든 연구소가 RSI 지표를 추적·공개 보고하도록 의무화해야 한다고 거듭 요구하면서도, 지표를 공개하는 것이 완전한 RSI를 추구하겠다는 뜻은 아니라고 강조했다.

## 왜 중요한가 (1인 개발자 관점)

1. **"어디까지 맡길 수 있는가"의 실측치**: 46%라는 숫자는 벤치마크가 아니라 실제 연구 조직의 내부 기록이다. 내 작업도 이 표에 비춰 볼 수 있다 — 모니터링·분석·소통은 맡기고, 서빙 스택 구축·환경 세팅은 사람이 잡는 식으로. [[patterns/agent-planning-to-implementation]]의 위임 설계에 그대로 쓸 수 있는 경계선이다.
2. **병목이 보인다**: 에이전트가 못하는 25%짜리 일(추론·서빙 코드)이 전체 속도를 묶는다. 빠른 부분만 빨라지면 전체는 느린 부분에 갇힌다 — 병목 이론의 교과서적 사례다. 내 워크플로우에서도 "가장 느린 단계"를 먼저 찾아야 한다.
3. **지출이 곧 의존도**: 연구원 1인당 하루 $2,400, 상위 10%는 $23,000. 인원의 40%를 내주고서라도 되찾겠다는 답은, 코딩 에이전트가 이미 "없으면 일을 못 하는" 인프라가 됐다는 뜻이다. 동시에 비용 관리가 곧 생산성 관리가 됐다.
4. **RSI 논쟁의 재료**: OpenAI가 "모든 연구소가 RSI 지표를 공개해야 한다"고 요구하면서 스스로 먼저 공개했다. 이 지표가 앞으로 규제 논쟁의 기준이 될 수 있다 — [[concepts/agent-scientific-discovery]]와 함께 지켜볼 축이다.

## 한계 (명시)

- 내부 추정치이지 독립 평가가 아니다. 에이전트가 유능해지면서 연구자들이 위임하는 과제의 종류도 바뀌었기 때문에, 성공률 상승이 순수한 모델 능력 향상이 아니다.
- 과제 소요 시간 추정치의 검증이 더 필요하고, 설문은 소규모·자기보고이며 인터뷰는 10명이다.
- $2,400·$23,000은 API 정가 환산이지 실제 지출액이 아니다.
- confidence는 medium — OpenAI 보고서 원문 + 다수 보도 교차이나, 보고서 전문 정독은 아니다.
