# 골드만삭스의 AI 코딩 도구 축소 — 엔지니어로 한정한 바이브 코딩 실험 종료

## 쉽게 읽기

**비유**: 전 직원에게 전동공구를 나눠줬다가, "숙련공만 쓰게 하자"고 회수한 셈이다. 도구가 나빠서가 아니라, 누가·어디까지 써도 되는지를 다시 그은 것이다.

| 용어 | 풀이 |
|------|------|
| **바이브 코딩** | 비개발자가 AI와 대화하며 앱 초안을 만드는 방식 |
| **strats** | 골드만의 퀀트와 엔지니어 업무를 겸하는 그룹 |

## 한줄 정의

2026-11-02 보도 — 골드만삭스가 10월 내부 지침으로 Claude Code와 Microsoft GitHub 코딩 도구를 엔지니어 중심으로 제한해, 트레이더·뱅커의 바이브 코딩 실험을 접었다.

## 핵심 내용

- **조치**: Claude Code와 Microsoft GitHub 도구의 접근을 엔지니어 중심으로 제한한다. strats는 계속 사용한다. 전체 약 47,000명 중 엔지니어는 약 12,000명이다.
- **배경**: 수개월간 트레이더·뱅커가 도구를 써서 고객 거래 흐름을 추적하고 포지션을 모델링하며 문서·그래픽 초안을 만들었다. 7월 CIO Marco Argenti는 비기술 직원의 바이브 코딩을 장려했고 엔지니어가 다듬는 인계 구조를 그렸다.
- **이유(회사 설명)**: 대변인 Nick Carcaterra는 "실험 기간을 거쳐 생산성과 리스크 관리를 포함한 여러 요소를 평가"한 뒤 "장기적으로 가장 잘 활용할 수 있는 사람들"에게 맡긴다고 밝혔다. 보안 사고 공개나 정량적 생산성 평가는 없었다.
- **아닌 것**: Anthropic과의 결별이 아니다. 방화벽 안에서 여러 모델(Claude 포함)로 돌아가는 자체 GS AI Assistant는 전 직원이 계속 쓴다. 제한된 것은 외부 에이전트가 직접 코드를 쓰고 실행하는 코딩 도구다.
- **대비**: BNY는 자체 Eliza 플랫폼에서 비엔지니어 구축을 허용하고, Deutsche Bank는 전문 개발자에게만 두되 주당 1.5~2.5시간 절감을 밝힌다. MUFG는 Claude Code가 정보 접근 제한을 우회할 수 있다며 자체 대안을 만들었다고 전해진다. 4월에는 홍콩 뱅커 대상 Claude 접근을 이미 제한한 바 있다.

## 왜 중요한가 (1인 개발자 관점)

1. **도입의 2막은 권한 정리다**: Menlo 보고서가 지출 급증을 보여준 같은 주에, 가장 까다로운 고객 중 하나가 접근을 좁혔다. 확산 다음에는 권한·감독·책임의 정리가 온다.
2. **에이전트의 실행 권한이 쟁점이다**: 조언하는 챗봇은 그대로 두고, 코드를 쓰고 실행하는 에이전트만 제한했다는 구분이 핵심이다. 에이전트에게 무엇을 실행하게 할지가 제품 설계의 경계선이다.
3. **금융권의 선례가 된다**: 규제 산업의 대형 고객이 그린 선은 다른 기업의 내부 정책 템플릿이 되기 쉽다. 기업용 에이전트를 팔 때는 역할별 접근 통제를 처음부터 제품에 넣어야 한다.

## 한계 (명시)

- Bloomberg 원문은 유료라 PYMNTS·Decoder 요약 경유로 확인했으며, 내부 지침 전문은 공개되지 않았다.
- 생산성·리스크 평가의 구체적 수치는 회사가 밝히지 않았다.
