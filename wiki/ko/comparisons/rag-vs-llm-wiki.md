# RAG vs LLM-Wiki

## 쉽게 읽기

**RAG**는 질문할 때마다 서랍에서 관련 문서를 **꺼내 읽고** 답한다. **LLM-Wiki**는 LLM이 **정리해 둔 노트(위키)** 를 계속 고쳐 가며, 다음번엔 “이미 요약·연결된 글”을 본다. 둘 중 하나만이 정답은 아니고 **목적에 따라** 섞기도 한다.

| 용어 | 풀이 |
|------|------|
| **RAG** | 검색으로 문맥을 붙인 뒤 생성 |
| **위키** | 페이지를 링크로 엮은 **지식 저장소** |
| **컴파일** | 원자료를 한 번 **가공해 두는 것** |

## 핵심 차이

RAG는 매번 원본에서 지식을 재발견하고, LLM-Wiki는 지식을 한 번 컴파일하고 지속적으로 유지한다.

## 비교표

| 기준 | RAG | LLM-Wiki |
|------|-----|----------|
| **지식 축적** | 없음 — 매번 재검색 | 있음 — 위키에 누적 |
| **교차참조** | 매번 다시 찾기 | 이미 연결되어 있음 |
| **모순 발견** | 매번 재발견해야 | 이미 플래그됨 |
| **종합/합성** | 매번 새로 합성 | 이미 종합되어 있음 |
| **유지보수 비용** | 낮음 (인프라만) | 중간 (LLM 비용 + Schema) |
| **초기 설정** | 쉬움 (업로드만) | 필요 (Schema 설계) |
| **규모 확장** | 임베딩/검색으로 확장 | 100+ 페이지 시 검색 엔진 필요 |
| **인간 개입** | 질문만 | 소스 큐레이션 + 피드백 |

## 언제 RAG를 쓸까

- 대량의 문서에 **일회성 질문**을 하는 경우
- 문서가 자주 바뀌지 않고, 교차참조가 불필요한 경우
- 빠르게 시작해야 하고, 설정에 시간을 투자하기 어려운 경우
- 정확한 인용이 중요한 경우 (법률, 규정 등)

## 언제 LLM-Wiki를 쓸까

- **시간이 지날수록 지식이 쌓이는** 주제인 경우
- 여러 소스를 **교차참조하고 종합**해야 의미가 생기는 경우
- 같은 주제를 **지속적으로 탐구**하는 경우 (연구, 학습)
- **정량 데이터가 아닌** 질적 지식이 주를 이루는 경우

## 결론

RAG와 LLM-Wiki는 대립이 아니라 **보완** 관계다. RAG는 "접근"에 강하고, LLM-Wiki는 "축적"에 강하다. 개인 학습이나 장기 리서치처럼 지식이 복리로 쌓여야 하는 경우 LLM-Wiki가 적합하다.
