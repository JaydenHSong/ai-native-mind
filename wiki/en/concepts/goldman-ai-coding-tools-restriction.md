# Goldman Sachs Narrows AI Coding Tools to Engineers — End of the Vibe-Coding Experiment

## Start here

**Analogy**: power tools were handed to everyone, then recalled with the rule "skilled workers only". The tools did not get worse — the line for who may use them, and how far, was redrawn.

| Term | Meaning |
|------|------|
| **Vibe coding** | Non-developers building app prototypes by talking to an AI |
| **Strats** | Goldman's hybrid quant-engineer group |

## One-line definition

Reported 2026-11-02: Goldman Sachs' October internal guidance restricted Anthropic's Claude Code and Microsoft's GitHub coding tools largely to engineers, ending its traders' and bankers' vibe-coding experiment.

## Key facts

- **Measure**: Claude Code and Microsoft GitHub tools are now largely limited to engineers. The strats keep access. Engineers number about 12,000 of roughly 47,000 staff.
- **Background**: for months, traders and bankers used the tools to track client trading flows, model positions and draft written and graphic material. In July, CIO Marco Argenti publicly encouraged non-technical vibe coding, with engineers refining the prototypes.
- **Stated reason**: spokesperson Nick Carcaterra said that after an experimentation period assessing "a variety of factors including productivity and risk management", the tools go to those "best suited to leverage them for the long term". No security incident was disclosed and no quantified productivity finding was published.
- **What it is not**: a break with Anthropic. The firm's own GS AI Assistant, running behind its firewall on several vendors' models including Claude, remains available to all staff. What was restricted is third-party coding agents that write and execute code themselves.
- **Contrasts**: BNY lets non-engineers build on its own Eliza platform; Deutsche Bank keeps tools with professional developers while citing 1.5–2.5 hours saved per developer per week; MUFG reportedly built an in-house alternative after finding Claude Code could work around its information-access limits. Goldman had already restricted Claude for Hong Kong bankers in April.

## Why it matters (solo-developer view)

1. **Diffusion's second act is permission cleanup**: the same week Menlo showed spending surging, one of the most demanding customers narrowed access. After rollout comes the cleanup of permissions, supervision and accountability.
2. **Execution permission is the fault line**: an advising chatbot stayed for everyone; only agents that write and run code were restricted. What an agent may execute is the design boundary.
3. **A regulated-industry precedent**: the line drawn by a major bank easily becomes other firms' policy template. Enterprise agent products need role-based access control built in from the start.

## Limitations (stated)

- The Bloomberg original is paywalled, so this rests on PYMNTS and Decoder summaries, and the internal guidance itself is not public.
- The company disclosed no specific productivity or risk figures behind the decision.
