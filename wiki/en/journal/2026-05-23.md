# 2026-05-23 Learning Journal — interface adaptation · terminal provenance · dual-surface tools · branchable sandbox

## How to read this page (30 seconds)

At first glance, today's four sources seem to cover different layers.

- Life-Harness = **interface mismatch** between the model and the environment
- TerminalWorld = where benchmark tasks **came from**
- HarnessAPI = how to unify **MCP and HTTP** as one capability
- DeltaBox = how quickly a sandbox can be **rolled back**

But in one line, they come together like this.

> **Agent engineering is now moving toward more precise design of interfaces, runtimes, and benchmark provenance outside the model itself.**

---

## 1. The four items collected today

### 1-A. Life-Harness — fix the interface to rescue a frozen model

**One line**: "The model may not be dumb; the model and environment may simply not be speaking the same language."

- paper title: **Adapting the Interface, Not the Model: Runtime Harness Adaptation for Deterministic LLM Agents**
- core framing:
  - in deterministic environments, many agent failures come from **model-environment interface mismatch**
  - the solution is **runtime harness adaptation** rather than model fine-tuning
- Life-Harness intervention layers:
  1. **environment contracts**
  2. **procedural skills**
  3. **action realization**
  4. **trajectory regulation**
- quantitative results:
  - **7 deterministic environments**
  - **18 model backbones**
  - improved **116 out of 126 settings**
  - **88.5% average relative improvement**
  - a harness evolved on Qwen3-4B **transferred to 17 other models**

### 1-B. TerminalWorld — bring real terminal workflow provenance into benchmarks

**One line**: "Terminal benchmarks should not rely only on human-crafted problem sets; they should also include workflows reconstructed from real recordings."

- paper title: **TerminalWorld: Benchmarking Agents on Real-World Terminal Tasks**
- benchmark construction method:
  - tasks are reverse-engineered from **in-the-wild terminal recordings**
- quantitative results:
  - **80,870 recordings**
  - **1,530 validated tasks**
  - **18 categories**
  - **1,280 unique commands**
  - **200 verified subset**
  - evaluation over **8 models / 6 agents**
  - best pass rate **62.5%**
  - correlation with Terminal-Bench **Pearson r = 0.20**
- key implication:
  - when reading benchmark scores, we should look not only at task difficulty but also at **task provenance**.

### 1-C. HarnessAPI — generate MCP tools and HTTP APIs from one skill

**One line**: "Instead of maintaining separate MCP surfaces for agents and HTTP surfaces for humans, derive both from the same skill contract."

- paper title: **HarnessAPI: A Skill-First Framework for Unified Streaming APIs and MCP Tools**
- core claim:
  - the same business logic often gets implemented twice for MCP and HTTP, causing drift
  - a typed skill folder + Pydantic schema becomes the **single source of truth**
  - from that, the system derives simultaneously:
    - **SSE streaming endpoint**
    - **OpenAPI / Swagger UI**
    - **zero-config MCP tool**
- quantitative result:
  - **6 representative skills**
  - **74% reduction in framework-facing boilerplate** compared with a manual dual-stack setup

### 1-D. DeltaBox — a sandbox is both a security mechanism and a search accelerator

**One line**: "If a long-horizon agent is going to explore many attempts deeply, the sandbox must be able to roll back quickly."

- paper title: **DeltaBox: Scaling Stateful AI Agents with Millisecond-Level Sandbox Checkpoint/Rollback**
- core contributions:
  - **change-based checkpoint/rollback** instead of full copies
  - **DeltaFS**: layered filesystem + copy-on-write
  - **DeltaCR**: incremental process-state dump + template-based restore
- quantitative results:
  - checkpoint **14ms**
  - rollback **5ms**
- key implication:
  - a sandbox is not just an isolation box; it is a **branchable runtime substrate**.

## 3. Connection points with existing knowledge

### 3-A. Harness Engineering now descends from policy to interface as well

Recent harness discussions had accumulated roughly like this.

- NLAH / CLAUDE.md = policy representation
- AHE / Insights Generator = observability-driven evolution
- Library Drift = skill lifecycle governance
- Code as Agent Harness = higher-level frame for code substrate

With today's Life-Harness, harness design gains one more question.

- **By what contract do the model and environment interlock?**

In other words, a harness is not only a constraint and verification mechanism; it is also an **interface translation layer**.

### 3-B. Eval now adds a benchmark provenance layer after environment realism

The existing eval axes were roughly these.

- judge reliability = JRH
- run disclosure = Benchmark Disclosure Audit
- surface vs truth = SpecBench / ResearchArena
- process controllability = ProcBench / HarnessAudit
- environment realism = WildClawBench

With today's TerminalWorld, a new question appears.

- **Did this task itself come from a real workflow?**

So now we need to examine not only environment realism but also **benchmark provenance**.

### 3-C. Tool Use becomes a deployment artifact beyond schema

If SkillSmith and Formal Skill already pushed tools/skills toward runtime interfaces and capability objects, HarnessAPI goes one step further by directly addressing the deployment problem of exposing the same capability through both:

- an **HTTP surface** and
- an **MCP surface**

That means tool definitions should now be read not as prompt-facing documentation but as a **capability registry with multiple operational surfaces**.

### 3-D. Sandbox is both a safety problem and a search problem

In the earlier safe-tool-calling view, the sandbox was mainly a security boundary. DeltaBox changes the question.

- How safely can it confine actions?
- How quickly can it rewind and retry?

That means the sandbox is both a security primitive and a **throughput primitive**.

## 5. Key learnings

1. **A harness is not only a policy layer around the model, but also the interface layer where model and environment meet.**
2. **In deterministic domains, interface adaptation can yield more than upgrading the model.**
3. **Real-world agent evaluation needs not only environment realism but also benchmark provenance.**
4. **Tool capabilities drift when MCP and HTTP are managed separately, so single-source deployment matters.**
5. **A sandbox is both a safety mechanism and infrastructure for branch exploration. Reset latency can determine agent throughput.**
6. **Trajectory logs are not just debug traces; they can also be training material for harness intervention rules.**
