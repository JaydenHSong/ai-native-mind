# 2026-04-12 Learning Journal

## Start here

This entry connected two operating questions:
- how humans and agents share responsibility inside software-engineering loops
- how OWASP-style LLM risks translate into practical TypeScript and harness design

## Key takeaways

- Martin Fowler’s **Humans and Agents in Software Engineering Loops** clarified the split between the **why loop** and the **how loop**.
- Pushing humans too deep into the low-level implementation loop can create a bottleneck.
- A better direction is to move quality checks earlier and make the harness able to measure more of its own work.
- The security side translated abstract LLM risks into practical controls around tools, approval, execution boundaries, and TypeScript validation.

## What changed in the wiki

- Strengthened [[concepts/harness-engineering]] with a sharper framing for human roles in agent loops.
- Connected security guidance to [[patterns/owasp-llm-typescript-mitigations]] and [[patterns/agent-server-harness]].

## Why it mattered

This was an early point where the wiki stopped treating agentic coding as only a prompting problem. The focus shifted toward loop design, verification placement, and concrete implementation safeguards.

## Follow-up

- Revisit how much review should stay **in the loop** versus move into harness-side verification.
- Keep linking security guidance back to tool boundaries and runtime controls.
