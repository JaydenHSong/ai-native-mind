# 2026-05-24 Learning Journal — source-level evolution · finance workflow eval · log-first runtime

## How to read this page (30 seconds)

Today’s three papers each look at a different layer.

- MOSS = what to do when a self-evolving agent needs to fix **code, not text**
- WorkstreamBench = how to evaluate a workflow agent by the **quality of the finished artifact**
- ActiveGraph = how to treat observability as **the runtime itself, not an after-the-fact log**

In one sentence:

> **Agent engineering is now moving beyond prompts and final answers toward jointly designing a modifiable substrate, an artifact that can be evaluated, and a replayable execution history.**

---

## 1. The three sources collected today

### 1-A. MOSS — self-evolving harnesses fix source code, not just text artifacts

**One line**: “If prompt edits do not fix a failure, the real problem may be hiding in harness code.”

- Paper: **MOSS: Self-Evolution through Source-Level Rewriting in Autonomous Agent Systems**
- Core framing:
  - Existing self-evolving agents mainly operate on **text-mutable artifacts** such as prompts, skills, memory schemas, and workflow graphs
  - But routing, hook ordering, state invariants, and dispatch live at the **code level**
- Method:
  1. Curate a batch of production failure evidence
  2. Run a deterministic multi-stage evolution pipeline
  3. Use an external coding-agent CLI to modify code
  4. Validate via ephemeral worker replay
  5. Promote with user-consent gating plus health-probe rollback
- Quantitative result:
  - On OpenClaw, the four-task mean grader score improved **0.25 → 0.61**

### 1-B. WorkstreamBench — workflow eval must assess not just cell correctness but output professionalism

**One line**: “Spreadsheet-agent evaluation should ask not whether one cell is correct, but whether the agent produces a financial artifact a human can actually continue using.”

- Paper: **WorkstreamBench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance**
- Core framing:
  - Existing spreadsheet benchmarks center on QA or single-formula edits
  - Real finance work is an **end-to-end artifact workflow** involving financial modeling, forecasting, and scenario analysis
- Evaluation taxonomy:
  - **Accuracy**
  - **Formula**
  - **Format**
- Key observations:
  - The Claude family leads
  - Even the strongest agents often fall short of professional finance standards
  - Performance drops sharply once tasks involve **a few chained calculations**

### 1-C. ActiveGraph — the log becomes agent substrate, not an observability appendix

**One line**: “Instead of building systems that leave good logs, let’s build systems that can come back to life from the log.”

- Paper: **The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems**
- Core framing:
  - Most agent frameworks start with the conversation loop and add logging later
  - ActiveGraph instead treats an **append-only event log as the source of truth**
- Three resulting properties:
  1. **deterministic replay**
  2. **cheap forking**
  3. **end-to-end lineage**
- Main implication:
  - Observability can become not just a debugging log but a **runtime contract**

## 3. Connection points with existing knowledge

### 3-A. Self-evolving harnesses move beyond skill lifecycle into source-level maintenance

Recently the wiki has been building the self-evolving harness line like this:

- AHE = observability-driven harness evolution
- Library Drift = self-evolving skill library hygiene
- Code as Agent Harness = higher-level framing for code substrate

With MOSS added today, the question drops one level deeper:

- **How far does the harness’s editable surface extend?**

That means self-evolution should now be read not as prompt or skill-text optimization, but as **harness evolution as a software maintenance loop**.

### 3-B. Evaluation now looks beyond workflow provenance to artifact professionalism

The recent evaluation axis has roughly looked like this:

- provenance = TerminalWorld
- disclosure = Benchmark Disclosure Audit
- process = ProcBench / HarnessAudit
- environment realism = WildClawBench
- feature complexity = FeatureBench

With WorkstreamBench added today, one more question attaches:

- **What rubric should measure the professional quality of the artifact itself?**

So in workflow-agent evaluation, an **artifact review rubric** matters more and more than a simple pass/fail.

### 3-C. Observability can move from trace collection to a log-first runtime

The existing observability discussion centered on:

- OTel semantic conventions
- Datadog 1,000+ traces
- AHE’s component / experience / decision observability

ActiveGraph pushes one step further:

- not just **collecting logs**
- but building **systems where the log is the source of truth**

So observability is not only an instrumentation-layer question, but also a question of **state-model choice**.

## 5. Core lessons

1. **The real bottleneck in self-evolving agents may be the design of the editable surface, not skill authoring itself.**
2. **Editing only prompt or skill text may fail to touch structural failures such as routing, hooks, and state invariants.**
3. **Workflow-agent evaluation must include an artifact professionalism rubric, not just answer accuracy.**
4. **In end-to-end business-artifact domains, Formula and Format matter as much as Accuracy.**
5. **Observability can become not just a logging feature, but a state contract that enables replay, forking, and lineage.**
6. **Branchable sandboxes (DeltaBox) and branchable event histories (ActiveGraph) solve the same ‘forkability’ problem at different layers.**
