# 2026-05-12 학습 일지 — 화요 데일리: 모델 아래 세 레버

## 이 글을 읽는 법 (30초)

오늘 자동 인제스트 3편은 **"모델은 거의 천장에 닿았다, 이제 모델 아래 layer에서 점수가 갈린다"**를 다른 각도에서 본다.

| 레버 | 질문 | 논문 |
|---|---|---|
| **Preparation** | 코드 짜기 전에 무엇을 끝내야 alignment가 들어 맞나? | Zigler, "Mise en Place for Agentic Coding" ([arXiv:2605.05400](https://arxiv.org/abs/2605.05400), 2026-05-06) |
| **Reliability** | 채점하는 LLM 자체는 reliable한가? | Dev et al. (RAND), "Judge Reliability Harness" ([arXiv:2603.05399](https://arxiv.org/abs/2603.05399), 2026-03-05) |
| **Grounding** | 도메인 무결성을 사용자 prompt보다 위에 둘 방법은? | Palmblad et al., "Epistemic Grounding via GROUNDING.md" ([arXiv:2604.21744](https://arxiv.org/abs/2604.21744)) |

## 한 그림으로 잇기

```
        User prompt
            │
            ▼
   ┌─────────────────────┐
   │  GROUNDING.md       │  ← (3) Field-scope, override user prompt
   │  (Hard Constraints) │     도메인 무결성 보장
   └─────────┬───────────┘
             ▼
   ┌─────────────────────┐
   │  MEP Phase 1-3      │  ← (1) Workflow-scope, implementation 전
   │  Briefing/Spec/Beads│     Context Fluency 산출물
   └─────────┬───────────┘
             ▼
       Agent execution (parallel subagents)
             │
             ▼
   ┌─────────────────────┐
   │  Judge Reliability  │  ← (2) Eval-scope, 채점자도 채점
   │  Harness (JRH)      │     format > semantic drop, task×model
   └─────────────────────┘
             │
             ▼
       Production deploy
```

세 layer 모두 *모델 위가 아니라 모델 아래*에서 작동한다. **prompt engineering이 invocation을 튜닝**한다면, 오늘 3편은 *invocation 위(GROUNDING.md), 옆(MEP), 뒤(JRH)*를 채운다.

## 각 편 한 줄

### (1) MEP — "vibe coding의 alignment 문제는 사실 preparation 문제다"

LinearB의 Andrew Zigler가 1st International Workshop on Vibe Coding and Vibe Researching(2026-06, Glasgow)에 출판할 논문. *Mise en place* (요리계 "모든 것을 제자리에")를 agentic coding 워크플로우에 이식한다. 3 phases:

1. **Contextual Grounding** — tacit knowledge를 markdown briefing 문서로 외화 (Polanyi externalization)
2. **Collaborative Specification** — *why*까지 포함한 spec, **무엇을 제외할지** 명시
3. **Task Decomposition** — Beads 같은 dependency-aware task records, parallel agent execution의 인터페이스

**케이스 정량 (5시간 hackathon)**: 준비 2hr → 9,386 단어 / 64 beads → 184 min × 4 parallel agents → 8,496 LOC / 43 beads closed (median **5.9 min/bead**). Planning-to-code **1.10:1**, prep-to-execute **5.7:1**, **architectural rework ≈ 0**.

**Context Fluency** = 새로운 개발자 skill, prompt engineering 상위. Decomposition / Specification / Constraint definition / Domain encoding 4 components.

### (2) JRH — "어떤 judge도 universally reliable 아니다"

RAND Corporation의 오픈소스 라이브러리. 4 frontier judge (GPT-4o, Claude Sonnet 4.5, Llama 4 Maverick 17B, Gemini 2.5 Pro) × 4 benchmark (FORTRESS / HarmBench / PERSUADE / AgentHarm) × 8 perturbation. 결론:

- **Format perturbation > semantic perturbation drop** — 의미보다 *공백·인덴트*가 더 큰 reliability 손실.
- **Reliability = task × model**, model property 아님. Claude는 binary 안정·ordinal 불안정, Gemini는 정반대.
- **Persuade(ordinal 1-6) 가장 fragile** — Sonnet 4.5 mean 37.26% / std **17.18%**.
- **AgentHarm asymmetric** — Opus 4.5 high-FN (subtle violation miss 31.3%), Gemini 2.5 Pro high-FP (corrected를 위반으로 25%).
- **Llama 4 Maverick 17B가 cost-reliability sweet spot** — Overall $0.0010/accuracy point (Sonnet의 1/22).

### (3) GROUNDING.md — "Hard Constraint가 사용자 prompt를 override한다"

Palmblad/Ragland/Neely의 짧지만 농밀한 proposal. 진화 단계:

1. Chat-based vibe coding
2. Agent scaffold + plan document
3. Project + method-scoped (CLAUDE.md / AGENTS.md / Skills)
4. **Field-scoped GROUNDING.md (이 논문)** — community-governed, prompt override

두 부분: **Hard Constraints** (non-negotiable scientific validity invariants, override user prompt) + **Convention Parameters** (community-agreed defaults).

매력 — *민주화와 무결성의 양립*. 비전문가가 도메인 코드를 빠르게 만들면서 도메인 전문가가 loop 안에 남는다.

## 합류점 — Convergence

세 편이 우연히 같은 시점에 떴는데, 실은 **모두 "agent 자율성을 어디서 잠가야 reliability가 생기는가"** 라는 한 질문을 다른 layer에서 답한다.

| 레버 | 잠금 메커니즘 | 어디서 작동 |
|---|---|---|
| **MEP** | phase-gating | implementation 시작 *전* (workflow 입구) |
| **GROUNDING.md** | Hard Constraints override user prompt | invocation *위* (도메인 무결성) |
| **JRH** | judge 자체 stress test | eval *뒤* (자동 채점자 보증) |

지난 PM 인제스트의 [[journal/2026-05-06-pm|CAAF (Harness as Asset)]]가 "H를 incorruptible asset으로 잠가라"였다면, 오늘 3편은 그 정신을 *세 layer에 분산 적용*한 것. 자율 진화 라인(Last Harness / AHE / Meta-Harness)이 "H를 똑똑하게 만든다"였다면, 결정적 잠금 라인이 다시 한 번 확장 — *결정의 책임을 어디까지 사람·커뮤니티·도메인이 가져갈지*가 reliability의 새 좌표축.

또 다른 합류점 — **Llama 4 Maverick 17B의 cost sweet spot**. JRH에서 judge로 sweet spot이고, [[journal/2026-05-03|Datadog 2026 보고]]의 70%+ 멀티 모델 사용 추세와 합쳐 보면, 1인 개발자의 model routing은 점점 **"하나 큰 모델 + 다수 cheap 모델"** 패턴으로 굳어진다 — judge·classifier·sub-task 용은 작은 모델, 중요 결정만 frontier.

## 메모

오늘 인제스트의 메타-관찰 — **연구가 LLM 위(prompt) → LLM 옆(context) → LLM 뒤(judge) → LLM 밖(community grounding) 순으로 outward expansion 중**. 모델 자체 progress는 둔화 신호가 보이지만 *"모델 주변 인프라"*는 폭발적으로 layered. 이 패턴이 정확하다면 1인 개발자의 ROI 함수는 더 이상 모델 선택이 아니라 **layer 선택** — 어느 layer에 얼마나 투자할지가 결정적.

[[journal/2026-05-03|Datadog 1,000+ 트레이스]]가 "프롬프트 캐싱 28%만 활용 / rate limit이 실패 모드 1위"라는 정량 진단을 줬다면, 오늘 3편은 *그 운영 부채에 layer 별 해법*을 제안 — preparation(MEP) / reliability(JRH) / grounding(GROUNDING.md). 데이터와 처방이 같은 흐름.
