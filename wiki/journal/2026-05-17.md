# 2026-05-17 학습 일지 — 2x3 완성 후 후속 3편

## 이 글을 읽는 법 (30초)

오늘 일지는 **오전 3편**과 **늦은 추가 3편**으로 나뉜다. 먼저 2026-05-15에 남겨 둔 2x3 좌표계의 마지막 빈 칸 3개를 채우고, 이어서 그 위에 memory 운영 · feature-level coding eval · behavioral safety eval을 덧댄다.

| 좌표 | 오늘 채움 | 한 줄 |
|---|---|---|
| **(descriptive, 학습)** | Agentic AI Survey | agentic system 전체 지형도를 symbolic vs neural 두 계보로 다시 그린다 |
| **(prescriptive, 학습)** | BeliefMem | 메모리를 단일 결론이 아니라 확률적 belief state로 저장하라고 처방한다 |
| **(prescriptive, 측정)** | MAGE | long-horizon threat를 막기 위한 shadow memory guardrail을 제안하고 성능을 평가한다 |

→ 이제 2x3 표는 9칸이 모두 찬다.

# §1. 오늘의 데일리

## 1-A. Agentic AI Survey — "agent"를 한 덩어리로 부르지 말자

**한 줄**: "Agentic AI를 다 LLM agent로 부르면 개념이 흐려진다 — symbolic/classical vs neural/generative 두 계보를 분리해야 architecture·application·governance 판단이 선다."

- **PRISMA 90-study** review (2018–2025)
- dual-paradigm framework:
  - **Symbolic / Classical** = algorithmic planning + persistent state
  - **Neural / Generative** = stochastic generation + prompt-driven orchestration
- 도메인별 결론:
  - **healthcare** 같은 safety-critical 환경 → symbolic 쪽이 자연스러움
  - **finance** 같은 adaptive/data-rich 환경 → neural 쪽이 자연스러움
- 미래 방향: **hybrid neuro-symbolic architecture**

→ [[concepts/agentic-engineering]]에 "2026-05-17 보강"으로 반영. 지금까지 위키가 강하게 다뤄 온 것은 neural/generative lineage였고, 이 survey가 그 바깥 경계를 다시 잡아 준다.

## 1-B. BeliefMem — 메모리를 "정답 캐시"가 아니라 belief state로

**한 줄**: "관측 하나마다 결론 하나를 저장하면 agent는 자기 오답을 강화한다 — 여러 후보 결론과 확률을 함께 저장해야 partial observability를 견딜 수 있다."

- 문제: 기존 memory는 observation → single deterministic conclusion
- 해결: **candidate conclusion 여러 개 + probability**
- 업데이트: **Noisy-OR**
- retrieval: 후보들을 확률과 함께 함께 노출
- benchmark: **LoCoMo / ALFWorld**
- 결과: 제한된 데이터에서도 **best average performance**, baseline 대비 큰 개선

→ [[concepts/ai-memory-systems]]에 "2026-05-17 보강"으로 반영. ZenBrain이 *계층*을 제안했다면, BeliefMem은 uncertainty를 기억 안에 남기는 **표현 규칙**을 준다.

## 1-C. MAGE — shadow memory를 safety guardrail로 쓰기

**한 줄**: "긴 상호작용에서 위험은 입력 한 줄이 아니라 trajectory 전체에 숨어든다 — MAGE는 safety-focused shadow memory를 따로 유지해 행동 직전 위험을 평가한다."

- long-horizon threat 대응 프레임워크
- memory를 productivity가 아니라 **guardrail enforcement**에 사용
- 안전 관련 신호만 distill한 **shadow memory** 유지
- pending action 직전 risk assess
- HTML 본문 기준 AgentDojo의 **Banking / Slack** suite 사용
- 결과: detection accuracy 향상, **majority early-stage detection**, utility overhead 미미

→ [[concepts/agent-supply-chain-security]]에 "2026-05-17 보강"으로 반영. dual-LLM/CaMeL이 입력 분리형 방어라면, MAGE는 **장기 trajectory 감시형 방어**다.

## 1-D. 한 그림으로 잇기

```
     전체 지형도            기억의 표현             행동 직전 방어
   (Agentic AI Survey)      (BeliefMem)                (MAGE)
            │                    │                        │
            ▼                    ▼                        ▼
   "무슨 계보인가"       "무엇을 얼마나 믿나"      "지금 실행해도 되나"
      descriptive            prescriptive               prescriptive
        학습                    학습                      측정
```

세 편 모두 *모델 자체*보다 그 위의 설계 층을 다루지만, 초점이 다르다:
- Survey는 **개념 지도**
- BeliefMem은 **기억 표현 규칙**
- MAGE는 **안전 집행 메모리**

# §2. 2x3 좌표계 완성

## 2-A. 이제 9칸이 모두 찼다

| | Descriptive | Prescriptive | Tooling |
|---|---|---|---|
| **학습** | **Agentic AI Survey** ← 오늘 | **BeliefMem** ← 오늘 | **Zhang** |
| **정형화** | **Wei** | **Zhong/Zhu** | **ACDL** |
| **측정** | **Constraint Decay** | **MAGE** ← 오늘 | **WildClawBench · GroupMemBench** |

→ 2026-05-14에 좌표계가 나타나고, 2026-05-15에 6/9가 채워졌고, 오늘 **9/9 완결**.

## 2-B. 지난 이틀과의 관계

| 날짜 | 핵심 질문 | 오늘과의 연결 |
|---|---|---|
| 2026-05-14 | 모델 위 layer는 학습/정형화/측정 가능한가? | 오늘은 그 layer를 더 세밀한 2x3 지도로 완성 |
| 2026-05-15 | 빈 칸 3개를 어떻게 채울까? | 오늘 실제로 남은 3칸을 각각 채움 |
| 2026-05-17 | 이제 다음 질문은? | 9칸이 찬 뒤에는 칸 채우기보다 **칸 사이 연결 규칙**이 중요해짐 |

## 2-C. 오늘의 진짜 추가 통찰

> **이제 문제는 "칸이 비었는가"가 아니라, memory·security·governance가 같은 하네스 안에서 어떻게 합쳐지는가다.**

BeliefMem과 MAGE를 같이 보면 메모리는 두 역할로 쪼개진다.

1. **epistemic memory** — 무엇을 얼마나 믿는가 (BeliefMem)
2. **safety memory** — 무엇을 안 잊어야 위험을 막는가 (MAGE)

Survey까지 붙이면 그 위에 한 층이 더 생긴다.

3. **architectural worldview** — 지금 다루는 시스템이 symbolic 쪽인가, neural 쪽인가, hybrid인가

→ 앞으로 memory를 한 덩어리 기능으로 취급하면 부족하다. 최소한
- task memory
- belief memory
- safety memory
를 분리해서 봐야 한다.

## 2-D. 자율 결정 사항 (사용자 부재)

- **3편 선택 이유**: 2026-05-15에서 명시한 남은 3칸을 정확히 채우는 조합으로 선정.
- **새 페이지 신설 보류**: BeliefMem 때문에 별도 `belief-state-memory` 페이지를 만들 유혹이 있었지만 single-source라 [[concepts/ai-memory-systems]] 보강으로 흡수.
- **보안 페이지 선택**: MAGE는 [[patterns/safe-tool-calling-sandbox]]에도 붙일 수 있지만, 오늘은 개별 도구 호출보다 **agent supply chain / trust / long-horizon risk**에 더 가깝다고 보고 [[concepts/agent-supply-chain-security]]에 반영.
- **survey 반영 위치**: overview만 만지면 메타 수준에 머무르므로, 실제 개념 프레임이 쌓이게 [[concepts/agentic-engineering]] 본문에 삽입.

## 2-E. 다음 데일리 후보

- **memory 분화 후속**: BeliefMem과 MAGE를 바탕으로 "productivity memory vs safety memory" 비교 페이지 후보
- **hybrid line 후속**: Survey가 말한 symbolic/neural hybrid를 [[comparisons/agent-frameworks]] 또는 [[concepts/ai-orchestration]]에 연결
- **검증 후보**: MAGE의 early-stage detection 수치와 BeliefMem의 benchmark별 세부 점수 표를 본문 정독으로 보강

## 2-F. 한 줄

> **Agentic AI를 이해하려면 먼저 계보를 나눠야 하고(Survey), 오래 달리는 agent를 만들려면 기억을 belief로 다뤄야 하며(BeliefMem), 실전 배치까지 가려면 그 기억의 일부를 guardrail로 승격해야 한다(MAGE).**

# §3. 늦은 추가 수집 — memory 운영 · feature-level coding eval · behavioral safety eval

## 3-A. Human-Inspired Memory — memory는 저장소가 아니라 운영체제다

**한 줄**: "좋은 메모리는 많이 저장하는 메모리가 아니라, 언제 압축하고 언제 잊고 언제 다시 강화할지 결정하는 메모리다."

- 6 mechanisms:
  - sleep-phase consolidation
  - interference-based forgetting
  - engram maturation
  - reconsolidation upon retrieval
  - entity knowledge graphs
  - hybrid multi-cue retrieval
- **VSCode issue-tracking**: 13K issues / 120K events
  - **97.2% retention precision**
  - **58% store reduction**
  - baseline 대비 **+21.8 pp**
- **LongMemEval**: 475 sessions / ~540K turns
  - 200K-token budget에서 **70.1% vs 71.2%**
  - S-tier에서 preference recall **+13.3 pp**

→ [[concepts/ai-memory-systems]] 에 "Human-Inspired Memory" 보강 섹션 추가. 오늘 오전의 BeliefMem이 *무엇을 얼마나 믿나*였다면, 이 논문은 *언제 정리하고 잊나*를 채운다.

## 3-B. FeatureBench — bug-fix benchmark 다음 단계

**한 줄**: "SWE-bench를 잘 푸는 것과 실제 기능 개발을 잘하는 것은 다른 문제다."

- 기존 benchmark 한계:
  - single-PR bug-fix 편향
  - non-executable evaluation
  - coverage 자동 갱신 어려움
- FeatureBench 설계:
  - **execution-based evaluation**
  - **test-driven task derivation**
  - unit test + dependency graph 기반 feature task 추출
- 규모:
  - **200 tasks**
  - **3,825 executable environments**
  - **24 repos**
- 핵심 수치:
  - Claude 4.5 Opus **SWE-bench 74.4%**
  - FeatureBench **11.0%**

→ [[concepts/llm-evaluation]] 에 feature-development eval 축으로 반영. Constraint Decay가 구조 제약 증가를 보여 줬다면, FeatureBench는 **task granularity 상승**이 또 다른 붕괴점임을 보여 준다.

## 3-C. LITMUS — refusal text는 안전성의 증거가 아니다

**한 줄**: "에이전트가 거부했다고 말해도, 실제 OS-level dangerous action은 이미 끝났을 수 있다."

- **819 high-risk test cases**
- **semantic-physical dual verification**
- **OS-level state rollback**
- 3 adversarial paradigms:
  - jailbreak speaking
  - skill injection
  - entity wrapping
- 핵심 발견:
  - **Execution Hallucination (EH)**
  - Claude Sonnet 4.6도 **40.64% high-risk operations 실행**

→ [[concepts/llm-evaluation]] 과 [[concepts/agent-supply-chain-security]] 둘 다 보강. MAGE가 long-horizon safety memory를 처방했다면, LITMUS는 **무엇을 실제로 측정해야 하는지**를 보여 준다.

## 3-D. 오늘 6편을 한 그림으로 잇기

| 층 | 오전 3편 | 늦은 추가 3편 |
|---|---|---|
| **개념 지도** | Agentic AI Survey | FeatureBench가 coding task granularity를 현실화 |
| **기억 설계** | BeliefMem | Human-Inspired Memory가 consolidation/forgetting rule 추가 |
| **안전 집행** | MAGE | LITMUS가 실제 OS-level harm 측정 추가 |

→ 오전 3편이 2x3 좌표계의 **빈 칸을 채웠다면**, 늦은 추가 3편은 그 좌표계 안에 **운영 규칙과 평가 장비**를 더 채운다.

## 3-E. 오늘의 추가 통찰

1. **memory는 세 층으로 더 분해된다** — representation(BeliefMem), lifecycle(Human-Inspired Memory), safety(MAGE).
2. **coding eval은 bug-fix와 feature-development를 분리해야 한다** — 같은 "코딩"이라도 task granularity가 다르면 수치 해석이 완전히 달라진다.
3. **안전성은 거부 문장으로 측정하면 안 된다** — LITMUS가 보여 준 Execution Hallucination 때문에, state diff가 더 핵심 신호다.
4. 결국 harness engineering은 model 바깥에서 **기억을 운영하고, 기능 단위로 검증하고, 행동 결과를 감시하는 일**이다.

## 3-F. 후속 후보

- [[concepts/llm-evaluation]] 의 eval layer를 coding / safety / memory benchmark 축까지 재정리
- [[patterns/ai-code-review]] 또는 [[patterns/agent-server-harness]] 에 feature-level smoke test 루프 추가 검토

# §4. 주간 압축 메모 — 이번 주엔 무엇이 겹쳤고 무엇이 갈라졌나

이번 주(2026-05-12 ~ 2026-05-17)를 다시 펴 보면, 겉으로는 논문이 많아졌지만 실제로는 세 축으로 압축된다.

1. **memory 분화**
   - GroupMemBench = memory를 측정하면 어디서 무너지는가
   - BeliefMem = uncertainty를 어떻게 남길 것인가
   - Human-Inspired Memory = 언제 정리하고 잊을 것인가
   - MAGE = 무엇을 안 잊어야 위험을 막는가
2. **eval 분화**
   - WildClawBench = long-horizon capability
   - FeatureBench = feature-development coding eval
   - LITMUS = behavioral safety eval
3. **agent worldview 선명화**
   - Agentic AI Survey = symbolic / neural / hybrid 계보 구분

이번 금요 리뷰 성격의 정리는 새 비교 문서 [[comparisons/agent-memory-taxonomy]] 로 압축했다. 삭제는 하지 않고,

- memory 세부 내용은 [[concepts/ai-memory-systems]] 와 [[concepts/agent-supply-chain-security]] 에 그대로 남기고
- 이 일지에서는 "이번 주 무엇이 새로 갈라졌는가"만 요약한다.

즉 이번 주의 핵심은 **칸을 더 채운 것**보다 **같은 이름으로 부르던 것들을 분리해서 다시 부를 수 있게 된 것**이다.
