# 2026-05-24 학습 일지 — source-level evolution · finance workflow eval · log-first runtime

## 이 글을 읽는 법 (30초)

오늘 3편은 각각 다른 층을 본다.

- MOSS = self-evolving agent가 **텍스트가 아니라 코드** 를 고쳐야 할 때
- WorkstreamBench = workflow agent를 **완성 산출물 품질** 로 재야 할 때
- ActiveGraph = observability를 **사후 로그가 아니라 런타임 본체** 로 볼 때

한 줄로 묶으면 이렇다.

> **agent engineering은 이제 prompt와 최종 정답을 넘어서, 수정 가능한 substrate·평가할 artifact·재생 가능한 execution history를 함께 설계하는 방향으로 간다.**

---

## 1. 오늘 수집한 자료 3편

### 1-A. MOSS — self-evolving harness는 text artifact를 넘어 source code를 고친다

**한 줄**: "prompt를 고쳐도 안 낫는 실패는, 실제로는 harness 코드에 숨어 있을 수 있다."

- 논문명: **MOSS: Self-Evolution through Source-Level Rewriting in Autonomous Agent Systems**
- 핵심 framing:
  - 기존 self-evolving agent는 prompt / skill / memory schema / workflow graph 같은 **text-mutable artifact** 위주
  - 하지만 routing / hook ordering / state invariant / dispatch는 **코드 레벨** 에 있음
- 방법:
  1. production failure evidence batch 큐레이션
  2. deterministic multi-stage evolution pipeline
  3. external coding-agent CLI로 코드 수정
  4. ephemeral worker replay 검증
  5. user-consent-gated promotion + health-probe rollback
- 정량:
  - OpenClaw에서 four-task mean grader score **0.25 → 0.61**

### 1-B. WorkstreamBench — workflow eval은 셀 정답이 아니라 산출물 professionalism까지 봐야 한다

**한 줄**: "spreadsheet agent 평가는 한 칸 맞추기보다, 사람이 이어서 쓸 수 있는 재무 산출물을 끝까지 만드는지 봐야 한다."

- 논문명: **WorkstreamBench: Evaluating LLM Agents on End-to-End Spreadsheet Tasks in Finance**
- 핵심 framing:
  - 기존 spreadsheet benchmark는 QA / single-formula edit 중심
  - 실제 finance는 financial modeling / forecasting / scenario analysis 같은 **end-to-end artifact workflow**
- 평가 taxonomy:
  - **Accuracy**
  - **Formula**
  - **Format**
- 핵심 관찰:
  - Claude family가 선도
  - strongest agent도 professional finance standard에 자주 미달
  - **few chained calculations** 를 넘으면 급격히 악화

### 1-C. ActiveGraph — log가 observability 부록이 아니라 agent substrate가 된다

**한 줄**: "로그를 잘 남기는 시스템이 아니라, 로그에서 다시 살아나는 시스템을 만들자."

- 논문명: **The Log is the Agent: Event-Sourced Reactive Graphs for Auditable, Forkable Agentic Systems**
- 핵심 framing:
  - 보통 agent framework는 conversation loop가 먼저, logging은 나중
  - ActiveGraph는 **append-only event log를 source of truth** 로 둠
- 결과 속성 3개:
  1. **deterministic replay**
  2. **cheap forking**
  3. **end-to-end lineage**
- 핵심 시사점:
  - observability는 디버깅 로그가 아니라 **runtime contract** 가 될 수 있다.

## 3. 기존 지식과의 연결 포인트

### 3-A. self-evolving harness는 skill lifecycle을 넘어 source-level maintenance로 간다

최근 위키는 self-evolving harness를 이렇게 쌓아 왔다.

- AHE = observability-driven harness evolution
- Library Drift = self-evolving skill library hygiene
- Code as Agent Harness = code substrate 상위 프레임

오늘 MOSS가 들어오면서 질문이 한 단계 더 내려간다.

- **하네스가 고칠 수 있는 표면은 어디까지인가?**

즉 self-evolution은 이제 prompt·skill 텍스트 최적화가 아니라, **software maintenance loop로서의 harness evolution** 으로 읽어야 한다.

### 3-B. eval은 workflow provenance 다음에 artifact professionalism까지 본다

최근 eval 축은 대략 이랬다.

- provenance = TerminalWorld
- disclosure = Benchmark Disclosure Audit
- process = ProcBench / HarnessAudit
- environment realism = WildClawBench
- feature complexity = FeatureBench

오늘 WorkstreamBench가 들어오면서 다음 질문이 붙는다.

- **산출물의 professional quality를 어떤 rubric으로 재야 하는가?**

즉 workflow agent 평가에서는 pass/fail보다 **artifact review rubric** 이 점점 중요해진다.

### 3-C. observability는 trace collection에서 log-first runtime으로도 갈 수 있다

기존 관측 논의는

- OTel semconv
- Datadog 1,000+ trace
- AHE의 component / experience / decision observability

중심이었다. ActiveGraph는 여기서 한 걸음 더 간다.

- **로그를 모으는 것** 이 아니라
- **로그가 source of truth인 시스템** 을 만들자

즉 observability는 instrumentation layer만이 아니라, **state model 선택** 의 문제이기도 하다.

## 5. 핵심 배움

1. **self-evolving agent의 진짜 병목은 skill authoring보다 수정 가능한 surface 설계일 수 있다.**
2. **prompt/skill 텍스트만 고쳐서는 routing·hook·state invariant 같은 구조적 실패를 못 건드릴 수 있다.**
3. **workflow agent 평가는 정답률만이 아니라 artifact professionalism rubric을 포함해야 한다.**
4. **end-to-end business artifact domain에서는 Accuracy만큼 Formula와 Format이 중요하다.**
5. **observability는 로그를 남기는 기능이 아니라 replay·fork·lineage를 가능하게 하는 state contract가 될 수 있다.**
6. **branchable sandbox(DeltaBox)와 branchable event history(ActiveGraph)는 서로 다른 층에서 같은 ‘forkability’ 문제를 푼다.**
