# 2026-05-19 학습 일지 — trajectory audit · virtual memory · natural-language harness

## 이 글을 읽는 법 (30초)

오늘 3편은 모두 **하네스를 더 낮은 시스템 층과 더 높은 문서 층으로 동시에 넓힌다**.

> **에이전트 성능은 모델이 아니라 하네스가 결정하는 부분이 크다는 말을, 오늘은 (1) 실행 궤적 감사, (2) 메모리 lifecycle 강제, (3) 자연어 정책 객체라는 세 방향으로 더 구체화했다.**

- [[concepts/llm-evaluation|LLM Evaluation]]: 정답 여부를 넘어 **trajectory boundary audit**
- [[concepts/ai-memory-systems|AI Memory Systems]]: memory를 retrieval store가 아니라 **virtual memory contract** 로 보기
- [[patterns/claude-md-guide|CLAUDE.md 작성 가이드]]: `CLAUDE.md`/`AGENTS.md`를 단순 설명서가 아니라 **natural-language harness policy** 로 보기

## 1. 오늘 수집한 3편

### 1-A. Auditing Agent Harness Safety

**한 줄**: "정답을 냈더라도, 중간에 금지된 자원 접근이나 잘못된 정보 공유가 있었으면 안전한 하네스가 아니다."

- **HarnessAudit**: trajectory 전체를 감사
- 축:
  1. **Boundary compliance**
  2. **Execution fidelity**
  3. **System stability**
- **HarnessAudit-Bench** 규모:
  - **210 tasks**
  - **8 domains**
  - **24 scenarios**
  - single-agent / multi-agent 둘 다 포함
- 본문 기준 핵심 발견:
  - **best overall score도 0.32**
  - completion과 safety는 **misaligned**
  - multi-agent는 **information-flow / resource-access violation**을 더 많이 만든다

→ 최근 위키의 WildClawBench / LITMUS가 runtime과 state diff를 보여 줬다면, 오늘 논문은 그걸 더 일반적인 **하네스 감사 프레임**으로 끌어올린다.

### 1-B. ClawVM: Harness-Managed Virtual Memory for Stateful Tool-Using LLM Agents

**한 줄**: "agent memory 실패는 종종 retrieval 실패가 아니라, flush/reset/writeback을 느슨하게 관리한 하네스 실패다."

- memory를 **typed pages** 로 나눔
- 각 page에 **minimum-fidelity invariants** 부여
- token budget 안에서 **multi-resolution representation** 선택
- lifecycle boundary마다 **validated writeback** 수행
- 본문 기준 수치:
  - **12 real-session traces**
  - budget 180 task replay에서 **100% success** vs baseline **76.7%**
  - overhead **18–44μs/turn**, p95 **< 60μs**

→ 지난 3일간 쌓인 BeliefMem / Human-Inspired Memory / MAGE가 memory의 **내용·신뢰·망각·안전**을 다뤘다면, ClawVM은 **그 기억을 런타임이 어떻게 잃지 않게 강제하느냐**를 다룬다.

### 1-C. Natural-Language Agent Harnesses

**한 줄**: "하네스의 핵심 재사용 단위는 코드가 아니라 정책이며, 그 정책은 자연어 문서로 분리될 수 있다."

- **NLAH**: run-level harness policy를 적는 자연어 문서
- **IHR**: 그 문서를 해석해 handoff / state update / validation gate / artifact contract를 실행하는 shared runtime
- 성능은 code harness와 대체로 비슷하면서 정책 표면은 훨씬 짧음
- 본문 기준:
  - **OSWorld**: NLAH **46.3** vs code harness **47.1**
  - **SWE Verified Live-SWE**: code **60.10k tokens / 68 files** vs NLAH **2.90k / 3 files**
  - **TB2 MHTBA**: code **10.50k / 3 files** vs NLAH **0.80k / 1 file**
- module 효과:
  - **file-backed state**: SWE **73.0 → 75.6**, OSWorld **44.4 → 58.3**
  - **verifier**: SWE **+0.2**, OSWorld **+8.4**
  - **context compression**: 두 벤치 모두 악화

→ `CLAUDE.md`, `AGENTS.md`, `SKILL.md`를 "메모"가 아니라 **policy module** 로 보는 현재 위키 방향을 강하게 지지한다.

## 2. 오늘의 연결 그림

| 층 | 오늘 소스 | 새로 선명해진 질문 |
|---|---|---|
| **실행 감사** | HarnessAudit | 작업이 끝났더라도 실행 도중 boundary를 어기지 않았는가? |
| **메모리 운영** | ClawVM | memory를 누가 lifecycle boundary에서 지키는가? |
| **정책 표현** | NLAH | 하네스 정책을 코드 밖 문서로 분리할 수 있는가? |

세 편을 한 줄로 압축하면 이렇다.

1. **하네스는 결과만 채점하는 껍데기가 아니라, 실행 과정을 계속 감시해야 하는 감사 substrate다.**
2. **메모리는 저장소 이름보다 lifecycle contract가 더 중요할 수 있다.**
3. **자연어 문서는 prompt 부스러기가 아니라, 잘 설계하면 실행 가능한 하네스 정책 표면이 된다.**

## 3. 기존 지식과의 연결 포인트

### 3-A. WildClawBench와 LITMUS 다음에 "audit framework"가 생겼다

기존 eval 축은 대략 이랬다.

- judge reliability ([[concepts/llm-evaluation]])
- runtime benchmark ([[concepts/llm-evaluation|WildClawBench]])
- behavioral safety / state diff ([[concepts/agent-supply-chain-security|LITMUS]])

오늘 HarnessAudit가 들어오면서 다음 칸이 생긴다.

- **trajectory-level boundary audit**

즉 이제는 "무슨 환경에서 통과했나"뿐 아니라 **"그 과정이 규정 위반 없이 흘렀나"**를 분리해 말할 수 있게 됐다.

### 3-B. memory taxonomy에 runtime enforcement가 붙었다

[[comparisons/agent-memory-taxonomy]] 가 memory를 task/productivity · belief · lifecycle · safety 네 층으로 나눴다면, ClawVM은 그 네 층 아래에 **runtime enforcement** 를 깐다.

- BeliefMem = 얼마나 믿나
- Human-Inspired = 언제 재구성하나
- MAGE = 무엇을 안 잊어야 안전한가
- **ClawVM = 그걸 어떻게 안 잃게 강제하나**

### 3-C. CLAUDE.md는 점점 harness document에 가까워진다

NLAH 덕분에 [[patterns/claude-md-guide]] 와 [[concepts/harness-engineering]] 의 관계가 더 단단해졌다.

- 예전 해석: `CLAUDE.md` = 프로젝트 설명서
- 오늘 추가 해석: `CLAUDE.md` = **project-scope natural-language harness policy**

즉 우리가 위키 운영 규칙을 markdown 문서에 두는 방식은 단순 편의가 아니라, **하네스 정책을 코드 밖 표현 객체로 두는 설계 선택**으로 볼 수 있다.

## 5. 핵심 배움

1. **안전한 에이전트는 정답을 내는 에이전트가 아니라, 정답에 도달하는 과정까지 감사 가능한 에이전트다.**
2. **memory 문제는 retrieval quality만이 아니라 flush/reset/writeback lifecycle의 문제다.**
3. **자연어 문서는 잘 설계하면 정책 코드의 대체물이 아니라, 정책의 더 portable한 표현이 될 수 있다.**
4. **multi-agent coordination은 성능뿐 아니라 정보 흐름 위반 표면도 함께 늘린다.**
5. **`CLAUDE.md` 류 문서는 prompt 보조자료가 아니라 harness policy artifact로 취급할수록 가치가 커진다.**
